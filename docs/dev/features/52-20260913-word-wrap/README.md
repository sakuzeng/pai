## 候选方案与确认

### 方案 A · 词边界回退（选定）

换行时若断点落在 ASCII 词中间，把整个词挪到下一行；词本身占满一行时不挪（否则永远放不下）。
词字符 = ASCII 字母数字 + `_`，于是 `rules.py` 允许在 `.` 处断、`MAX_OUTPUT_CHARS` 整体移动。
挪走后上一行末尾的空格一并剥掉——尾随空格在选区复制时会被带出来。
代价：行尾可能留几列空白，长 URL 尤其明显。

### 方案 B · 带连字符断词

`read-\nfile`。要一套音节规则，做不好比劈开更难看，且中英混排时连字符与全角标点打架。

### 方案 C · 维持逐字符，继续扩 `NO_LINE_START`

44 交付时就是这么做的，44 复盘已经否掉：那是用排版规则补算法的洞，英文标点顶行首本来就不该发生。

### 确认

问 1：怎么断词？
- 候选 A·词边界回退。
- 候选 B·连字符断词。
- 候选 C·维持逐字符 + 扩标点表。
选择：A。用户原话「做一个最关键的功能」= 从六条里只做这一条，断词方式沿用档案立项时我建议的 A
（B 要音节规则、C 已被 44 复盘否掉，两条都没有重新讨论的余地）。

问 2：词字符包含哪些？
- 候选 A·ASCII 字母数字 + `_`（`.` `/` `-` 不算，于是路径与文件名可以在分隔符处断）。
- 候选 B·把 `.` `/` `-` 也算进去（整条路径不可断）。
选择：A。理由：`src/pai/tui/markdown.py` 这种长路径若整条不可断，窄屏下会整行挪走、留大片空白；
在 `/` 处断开仍然读得出来，而在 `mark|down` 中间断开读不出来。

## 结果与总结

交付（2026-09-13）：模型回答里的英文单词不再被折行劈开。

- `tui/markdown.py::_wrap_spans` 的换行分支重写：换行时算「本行留几个字」，避头与补词两条规则
  依次作用；新增 `_is_word_char`（ASCII 字母数字 + `_`）。顺带剥掉折行留下的行尾空格。
- 真正的成因与三轮前登记的不同：劈开 `rules.py` 的是 44 那条 ASCII 标点避头（把 `s` 挤下来陪句点），
  不是「断点落在词中间」。加调试打印跑一遍断点才看见，过程记在 devlog。
- 测试：`tests/test_markdown_wordwrap.py` 6 组，按宽度 24..80 区间跑（44 复盘那条经验第一次当主力用，
  81 个宽度里只有 3 个会红）；44 的 28 条测试全绿。注入反证 `34 failed`。
