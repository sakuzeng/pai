## T1 · KeyDecoder 认时间（问 1）

- `KeyDecoder.__init__` 收可注入的 `now`（默认 `time.monotonic`），
  每次 `feed()` 进字节时记 `_last_byte_at`。
- `flush()` 加判据：缓冲区只有 `\x1b` 且距最后进字节 ≥ `ESC_SETTLE_SECONDS`
  才裁决为 esc；否则原样留着。
- 常数写来源：人按 Esc >100ms、终端发序列 <1ms，取 50ms。
- 测试（≥4）：拆包到达不被裁决 / 真超时后裁决 / 原键照常送达 /
  假时钟注入。反证：去掉时间判据 → 拆包那条变红。

## T2 · pasting 态自愈（问 2）

- `flush()` 里加第二条分支：`_pasting` 且距最后进字节 ≥ `PASTE_SETTLE_SECONDS`
  → 把 `_paste` 已攒内容按 paste 键吐出、复位 `_pasting`。
- 阈值比 T1 大一个量级（粘贴分片间隔可达数百毫秒），取 1.0s，写清理由。
- 测试（≥3）：丢失 `201~` 后键盘恢复 / 正常粘贴不被误切 /
  复位后普通按键照常。反证：去掉复位 → 键盘恢复那条变红。

## T3 · `\x1b` 与后续字节同批到达（问 1 的邻居，实测顺带撞出）

连按两次 Esc 现在得到一个 `unknown '\x1b\x1b'`，一个 esc 都不产生。
- 判据：`\x1b` 后面紧跟的若不是 `[`/`]`/`O` 这类序列引导符，就把前一个
  `\x1b` 当独立 esc 吐出，剩下的继续解析。
- 测试（≥2）：连按两次 Esc 得到两个 esc / 正常方向键不受影响。
- 归入本轮的理由：与 T1 同一个函数、同一批测试，拆开要动两次。

## T4 · SIGWINCH 只置标志（问 3）

- `TerminalSession.handle_resize` 改为只更新尺寸 + 置 `resize_pending`，
  不再调 `_on_resize`。
- `TuiDriver.poll()` 醒来时检查标志，真变了才重画（同尺寸丢弃的语义保留在
  `handle_resize` 里，不搬家）。
- 非 TUI 调用方（若有）要一并核对。
- 测试（≥3）：信号处理器不写 stdout / poll 后确实重画 / 同尺寸仍丢弃。
  反证：把重画搬回处理器 → 「处理器不写 stdout」那条变红。
- 交付时在 decisions 记一条对 feature 12「同步处理」的复议（不推翻「不去抖」）。
