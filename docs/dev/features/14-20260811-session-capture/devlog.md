# 14-session-capture · 开发日志

## 2026-08-11 立项

**目标**：让 AI 自己看得见 pai 的界面，不必每次让用户截图。
起因是 feature 12 的四轮视觉修正全靠用户截图往返——**我一次都没先于用户发现问题**。

**拍板**：方案 B（pai 自带录制）+ PIL 出图。
顺带把终端模拟器从 `tests/tui_screen.py` 升为 `src/pai/tui/screen.py`，
回放与测试共用同一份——**测试里断言的屏幕，与出图看到的屏幕，是同一个东西**。

## 2026-08-11 交付

**改动**：

  `strict` 开关）；`tests/tui_screen.py` 保留为转发入口，747 条既有测试零churn

**红→绿**：新增 9 条（8 条录制/回放 + 1 条 emoji 守卫），`./test.sh` **756 passed**。

**端到端验过**：真 pty 跑 pai（`/help`、shift+tab、`!echo`、中文输入）→ 录制 31KB
→ 回放出 PNG → **AI 自己读那张图**。

**第一次出图就撞了一个自己的坑**：字体路由写成「`ord > 0x2000` 就当中文」，
于是 `›`(U+203A)、`█`(U+2588)、`─`(U+2500) 全被丢给中文字体渲染成方块——
**出图工具自己的假象**，差点让我去追不存在的 pai bug。
改成按真正的 CJK 区间路由 + 逐字查字体覆盖，**查不到的字报出来**
（"图上会是方块，与 pai 无关"）。
教训写进代码注释：**出图工具报的每一个「问题」，都要先排除是它自己的。**

**出图之后自己发现的第一个真问题**：`🔐 权限模式 →` 是 feature 12 我自己写的
TUI 侧文案，**违反我自己立的 D#63**（界面字形不用 emoji）。已改成 `[权限]`，
并加了一条守卫测试：`_run_tui` 的源码里出现任何 emoji 码位即变红。

**遗留**：
- 录的是 pai 的**输出流**，不含用户按键——回放看得到界面、看不到「用户按了什么」。
  要复现操作序列还得靠探针脚本。
- 出图用的是 macOS 自带字体的硬编码路径，换平台即失效（pai 目标平台是 macOS/Linux，
  Linux 上要另找字体）。
- 彩色 emoji 画不出来（PIL 不支持 Apple Color Emoji），图上是方块——
  已由「缺字报出来」兜住，不会被误认成 pai 的问题。
