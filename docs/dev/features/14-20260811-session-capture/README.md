## 需求

**让 AI 自己看得见 pai 的界面**，不必每次都让用户截图。

用户 2026-08-11 原话：「主要是对话界面是否可以捕获呢…有了这些信息之后你就可以发现问题和
美化的地方了，每次都要我去截图有点太麻烦了」。

背景是 feature 12 交付后的四轮视觉修正**全部靠用户截图往返**——
我有 747 条测试、有终端模拟器、有 pty 探针，但**一次都没有先于用户发现问题**，
因为我从来看不见「屏幕上最后长什么样」。

### 验收标准

1. `PAI_TUI_RECORD=<路径> pai` 把 pai 写给终端的**全部字节**录下来（含终端尺寸与 resize）。
2. 一条命令把录制**回放成一张 PNG**，颜色/粗细/背景色带全部还原。
3. AI 能直接读那张 PNG，从而自己判断排版与配色问题。
4. 录制默认**关闭**，开启后对 pai 的行为零影响（只是 tee 一份字节）。
5. 中文与半块字符（logo）渲染正确。

## 候选方案与确认

### 方案 A · `script(1)` 外壳录制

macOS 自带 `/usr/bin/script`，`script -q out.txt pai` 即可录下全部字节，pai 零改动。

- **对**：零代码。
- **缺**：录不到终端尺寸与 resize 事件（回放时不知道该按多宽还原）；
  录的是**双向**流（含用户输入回显），要额外剥；用户得记住换个命令跑。

### 方案 B · pai 自带录制（选它）

`DockRenderer` 的 `write` 是注入的，包一层就能 tee。格式用 JSONL：
每条 = `{t, cols, rows, data}`，resize 时补一条尺寸记录。

- **对**：录得到尺寸与 resize；只录 pai 的输出流（干净）；一个环境变量，不用换命令。
- **缺**：要在 pai 里加十几行。

### 方案 C · asciinema

标准格式、生态好。**本机未安装**，且引入外部依赖与项目「从零实现」的定位不符。

### 确认

**问**：怎么让 AI 自己看见界面？
**选择**：**方案 B + PIL 出图**。理由：A 录不到尺寸（而 resize 正是已知的问题多发区），
C 要装东西。B 只加十几行，且顺带把「终端模拟器」从测试基建升为一等公民
（`src/pai/tui/screen.py`），回放与测试共用同一份实现——
**测试里断言的屏幕，与出图看到的屏幕，是同一个东西**，这条比省几行代码重要。

## 结果与总结

**AI 现在能自己看见 pai 的界面了。**

```bash
PAI_TUI_RECORD=/tmp/s.jsonl pai        # 录（默认关闭，开了也只是 tee 一份字节）
pai-replay /tmp/s.jsonl -o /tmp/s.png  # 回放成 PNG
pai-replay /tmp/s.jsonl --text         # 只要文本
```

关键一步是**把终端模拟器从测试基建升为一等公民**（`tests/tui_screen.py` →
`src/pai/tui/screen.py`，加 SGR 配色跟踪与 `strict` 开关）：
回放出图与测试断言**共用同一份**——分成两份的话，「测试全绿」与「图上是对的」
会各说各话。747 条既有测试零改动（保留转发入口）。

端到端验过：真 pty 跑 pai → 录制 31KB → 回放出 PNG → **AI 读那张图**，
并当场自己发现了第一个真问题（见下）。`./test.sh` **756 passed, 3 deselected**。
