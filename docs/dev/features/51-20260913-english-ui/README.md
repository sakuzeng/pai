## 需求

出处：feature 50 交付后连续三轮真跑反馈的终点。用户先要「只需要有英文的 Ran num shell commands」
（已在 50 的补丁里做掉），我随后登记「组摘要英文而 dock / 帮助行 / 对话框仍中文，同一屏两种语言」，
并问用户要不要一并改；用户选「整个 TUI 全改英文，然后合并」。改的是 05/12/13/16/44/49/50 等多次
交付的文案，旧档案冻结，本档案链回。

一句话：pai 对人说的每一句话都改成英文；给模型看的、落盘的、文档与注释一律不动。

判据（这次交付真正的产物——没有它，下次加功能又会混进中文）：

- 改：经 `out` / `commit` / `print` / `warn` 到达屏幕的文本。包括 TUI 的所有渲染（dock、对话框、
  工具组、事件渲染 `render_text`、退出摘要）、REPL 的提示与错误、`/命令` 的全部输出、权限弹窗的
  问句与选项、`cli.py` 的 `--help` 与参数错误、`pai-viz` / `pai-replay` 的 CLI 输出。
- 不改：① 进 `messages` 的文本（system prompt、工具描述、工具返回的结果与错误字符串、
  `INSTRUCTION_HEADER` / `SUMMARY_HEADER` / `shell_echo` 这类既是模型可见又是回放解析格式的常量）；
  ② 落盘字段与会话格式；③ 代码注释、docstring、`docs/`、`knowledge/`、`README.md`
  （AGENTS.md 的中文写作规约不变，这次动的是运行时的界面，不是仓库的语言）。
- 边界上的两条具体裁决：工具结果既给模型也显示给人 → 按「模型可见优先」不改；
  `ask_user_question` 的问题文本来自模型 → 不改，但它周围的框架提示（「输入序号或自己的话」）要改。

验收标准（怎么算做完）：

- 守卫一（lint，强）：`src/pai/tui/**.py` 的非 docstring 字符串常量一律不含 CJK。tui 层只画界面，
  混进中文就是漏网。
- 守卫二（行为）：驱动 REPL 与 TUI 的主要路径（启动、一轮工具调用、权限弹窗、`/help` `/status`
  `/memory` `/mode` `/permissions` `/compact` `/clear` `/resume`、`!命令`、错误与中断、退出），
  抓屏幕文本断言不含 CJK——用户输入与模型回答除外（那两样本来就可能是中文）。
  诚实边界：守卫二只覆盖被驱动到的路径，没驱动到的靠 lint 与评审。
- 既有测试全部改到新文案，`./test.sh` 全绿，数字贴 devlog。
- 抽查 `pai --help` 与一次真跑的截图，确认没有半中半英的行。

非目标：

- 不做 i18n 框架（语言开关、消息目录）。用户要的是英文界面，不是多语言——加一层间接只会让
  「文案在哪」更难查。哪天真要中文回来，那是另一次交付。
- 不动 system prompt 与工具描述：它们是给模型的，且 feature 46/47 刚用可重复测量校准过中文提示词，
  换语言等于推翻那轮结论。
- 不动文档与注释。

## 候选方案与确认

### 方案 A · 全量替换 + 双守卫（选定）

一次把界面文案换成英文，配 lint 与行为两条守卫钉住。代价是改动面大（src 约 200 处、测试约 100 处），
但一次做完；守卫保证以后不回潮。

### 方案 B · 只改 TUI 层，命令输出留中文

改动面小一半，但 `/help` 与权限弹窗恰恰是用户提到的「同一屏两种语言」的主要来源，等于没解决。

### 方案 C · 加语言开关（i18n）

`settings.json` 里 `ui.language`，两份文案表。看起来最周全，实则把一次替换变成永久的双份维护，
而 pai 是学习项目、只有一个用户。CC 与 pi 都只有英文一种。

### 确认

问 1：范围？
- 候选 A·整个 TUI 全改英文（含 `/help` 表、权限弹窗、命令输出）。
- 候选 B·只改状态类文案（dock / 帮助行 / 对话框），命令输出保持中文。
- 候选 C·不改，维持现状。
选择：A。用户在选项里点的就是 A，原话「整个 TUI 全改英文，然后合并」。

问 2：要不要做语言开关（i18n）？
- 候选 A·不做，直接替换。
- 候选 B·做 `ui.language` 两份文案。
选择：A（本档案方案 A 的一部分）。理由：CC 与 pi 都只有英文；双份文案在单人项目里是纯负担。
真要中文回来时立新档案。
