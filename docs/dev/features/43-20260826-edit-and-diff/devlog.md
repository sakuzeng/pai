## Task 1 · 抽出 `roots.py`（2026-08-26）

目标：`search_root` / `test_root` / `repo_root` 三份形状一样的根解析 + 三份形状
一样的 matcher 包装收成一处。纯结构改动，行为必须逐字不变。

验收按用户点名的判据做成对照表：`tests/test_tool_roots.py` 把抽取前的三份实现
原样抄进测试当对照组，10 组输入 × 三个工具逐个比对新旧结果。
「测试还绿」在这里不是判据——三个工具的既有测试本来就绿，抽错了它们多半还绿。

抽取顺带显式化了一处原本靠巧合成立的东西：`git_read` 没有 `path` 参数，
它那份实现「碰巧不读 args」。统一成「取 args 的 path」会造出一个真洞——
权限层判的是 args 里那个路径，而 git 实际跑在 cwd（`-C` 在拒绝名单里，
它换不了目录），判定的路径与实际跑的路径不是同一个。所以 `root_getter` 收
`param=None`。

绿：三个工具 + 对照表 `87 passed`；快循环 `1571 passed`。

注入反证三条，两条红（丢掉 cwd 回落 → 8 红；matcher 不解默认根 → 2 红）。

第三条**没红**，而且两次都没红：把 `param is None` 那个分支删掉、再把
`param and isinstance(...)` 里的 `param and` 删掉，行为一个字不变。
按 mutation-testing-pitfalls 第五条查实现——实现没错，但**我对它的理解错了**：
真正让 `param=None` 无视 args 的是 `args.get(None)` 本来就取不到任何东西，
那行守卫是写给读代码的人看的，不是机制。没有任何输入能把它与「删掉」区分开。
处理是把注释改成实话（「别以为它在防什么」），既不删掉也不编一条测不出的测试。

## Task 3 · diff 呈现（2026-08-26）

新增 `core/tools/diffs.py`，`edit_file` / `write_file` 的返回值都带一段 diff。
`write_file` 为此在写之前多读一次盘（读不出来绝不能挡住写本身，所以吞掉异常
并如实标记）。

红：模块不存在。绿：`tests/test_tool_diffs.py` `14 passed`；快循环 `1591 passed`。

有一条测试专门钉**两边的连接处**：`_hidden_rows(ToolEnd(result=...)) > 0`。
diff 渲染得再好，如果结果被压成一行，TUI 那套现成的折叠/展开机制就用不上。

注入反证七条，五条一次就红。两条的处理值得记：

一、`n=0` 那条不红。查下来是**我的注释在撒谎**：它写着「不这样会把改动量算成
diff 长度」，而上下文行以空格打头、`@@` 以 `@` 打头，两者本来就落不进 `+`/`-`
的计数——`n=0` 换成 `n=3` 结果一模一样。`n=0` 只是更便宜。注释改成实话。

二、剥文件头那条不红。同样先查实现，实现是对的，是我的用例挑错了方向：
新增的 `---` 在 diff 里是 `+---`，全文过滤 `startswith("---")` 碰不到它；
真正会被误删的是**被删掉**的那一行——`-` 加 `---` 正好是 `----`，当场命中。
改用例后注入即红。
