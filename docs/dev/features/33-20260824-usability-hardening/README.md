## 需求

用户原话（2026-08-24）：「把当前的 pai 做到能够让人使用的程度，不要求有
新的功能但已有的功能要健全然后提交」。

解读：不加新能力；把已交付功能里登记在案的用户可见缺陷修掉，把面向用户的
文档（README）从陈旧状态刷新到与现状一致——现在的 README「已知缺口」还写着
没有 skills/MCP/--resume/alt-screen（全部早已交付），测试数字停在 1069
（实际 1377），新用户按它认知会错过一半功能。

验收标准（怎么算做完）：

1. 折行续排行上的鼠标点击定位正确（21 遗留 1）：点第二段落在正确字符，
   有离线测试钉住（修前红）；
2. 粘贴自愈不再静默（19 遗留 2）：`PASTE_END` 丢失自愈吐出内容时带一行提示；
3. `/permissions` 说全真话（09 遗留 1 提示半边 + 遗留 3）：明确提示
   「bash 不参与目录边界，配 allow 白名单即可越界」+ 列出危险路径清单；
4. once 下配置的 `defaultMode` 需要真人时告警一次，不再静默合流（09 遗留 2）；
5. MCP 根级非对象 inputSchema 不再原样透传（29 复核 R6）：warn + 跳过该工具，
   不让坏 server 的 schema 直达 API 撞 400；
6. 超高 dock（粘几千字符）有明确定义的行为（21 遗留 3）：不崩、可用，有测试；
7. 折行长行上 ↑/↓ 先在显示行间移动光标、到边界才翻历史（21 遗留 2，CC 同款
   语义）——「想上移光标却换出历史」是折行交付里最容易撞的缺陷；
8. README 刷新到与现状一致：CLI 全部参数、REPL 全部命令、settings.json
   全部键（permissions/defaultMode/tui/bash.timeoutSeconds/mcpServers/hooks）、
   skills 与 MCP 的配置方法、eval.sh、数据布局、真实的已知缺陷段；
9. `./test.sh` 全绿，数字进 STATUS；逐条注明刻意不做的。

刻意不做（同样是「健全」但不属本次）：拖选卡顿与 pty 挂死（未确诊，等复现，
硬做就是再猜一轮）；校准类常量（等真实使用数据）；skills 中途 reload、
MCP 远程传输等（新能力，用户明说不要求）。
