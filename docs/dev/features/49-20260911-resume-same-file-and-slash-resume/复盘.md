## 学到了什么

「就地变更」这条路在 pai 里走到了第六件。CC 的 `switchSession` 也是就地改全局状态，
所以这轮照 CC 做并不别扭：messages / ledger 用切片赋值、SessionLog 就地换文件、EventTrace 改成
按 session 当前路径算，装配期烤进闭包的引用一个都不用动。但正因为顺手，才更要写下：
`/resume` 一次换六件东西、散在四个模块里，靠的是我记得全——24 复盘说「到第四件该封对象」，
现在是第六件。这轮没封是拍板过的（问 3），债在 TODO 里更明确了。

第二条：一条注释救了一个静默漏。events.py 在 feature 37 写下「将来 resume 重建这类第三种改写
方式出现时，往这里加一行——忘了加就是静默漏」。这轮先写的纵切测试（切换前召回过的记忆切换后
要能再选中）在拿掉发事件那一行时红了——如果没有那条注释，我大概会在 `/resume` 做完之后才想起
召回去重表，或者根本想不起。把「下一个人会漏什么」写在会漏的位置，比写在文档里有用。

第三条：24 的取舍不是错的，是被新需求推翻的。「自包含新文件」防的是 CC 反教材里的指数增长，
在只有 CLI resume 的世界里成立；`/resume` 进程内反复切换让复制全量历史的代价从「每次启动一份」
变成「每次切换一份」，取舍就反了。决策记录里写清「当时为什么对、现在为什么不对」，比改掉它更重要。

第四条（交付后一小时补的）：真用一次抓到的洞比整套测试快。选择框把 `pai_playground/skills-smoke`
的会话列了出来——所有测试都在一个 tmp 目录里录、在同一个目录里恢复，"同一仓库的子目录"
这个形状根本不在测试里。sessions 目录按 git 根归档是 feature 08 的取舍，它与「按当前目录挑会话」
并不矛盾，只是需要在挑的时候看一眼 header.cwd；CC 因为按 cwd 归档，天然没有这个问题。

## 我现在质疑什么

- 重装配的 system 不落盘。文件里的 system 于是永远是首次录制的版本，`replay_messages`（evals
  回放）拿到的是旧 system。CC 的根治是 system 不进转录，pai 格式 v1 存了它——这轮的做法是
  能做到的最接近形态，但「盘上的 system 与模型看到的不是同一份」这件事从此存在。格式 v2 时该一起解。
- 指令消息「变了才追加」。功能正确（`build_messages` 只取最新），但长期反复 resume 的文件里会
  积累多条几 KB 的指令消息，体积账没算。
- `recent_sessions` 为了三样信息（时间 / 条数 / 首句）把每个候选文件整个解析一遍。八个文件今天
  几十毫秒，会话多起来就不是。CC 分 lite log 与 full log 两级，pai 若要做只需读前几行。
- `--fork-session` 是为「照 CC」保留的，pai 目前没有 fork 的动机（没有 plan 文件、没有 worktree
  要隔离）。一条没人用的路径也要维护——如果半年后还没人用过，该考虑删。
- 选择框只排除当前文件、只列本项目。跨项目、搜索、标题都是 CC 有 pai 没有的；先不做是对的，
  但「最近 8 个」这个数是凭手感定的。
