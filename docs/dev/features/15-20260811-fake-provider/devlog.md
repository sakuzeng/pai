**三条注入反证——过程本身比结果值钱**

三条 e2e 各对应一条用户打回的 bug。第一轮注入下来 **只有 1 条打红**，
另两条是**假绿**。逐条查清：

1. **答案不上屏**：我的注入只删了一半（`AssistantMessage` 不上交），
   而 `AgentEnd` 分支里还有一次 `_flush_answer`。忠实还原（连 `MessageDelta`
   一起丢）之后就红了。**是注入不对，不是测试不对。**
2. **排版阶梯**：第一版断言「没有行超过终端宽度」——**虚拟屏与真终端一样会自动折行，
   永远不越界**，这条断言什么都没测。改断言「dock 三行的结构」仍不红。
   查到真因：**阶梯的症状是 raw mode 下 `ONLCR` 关着、裸 `\n` 只下移不回列首**，
   而工具结果如今折叠成一行、答案在 `_answer_lines` 里已拆好——
   **原 bug 的入口已经不存在了**。最后找到仍会把整个多行字符串交给 `commit` 的
   现存路径（`/help`），钉在那里才打红。
3. **权限框卡死**：一次就红。

教训写进复盘：**注入反证不红时，先分清是「注入不对」「断言不对」还是
「这条路径已经不存在」——三者的处理完全不同。**
