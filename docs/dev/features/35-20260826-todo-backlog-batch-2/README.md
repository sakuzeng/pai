- 候选 A·上下文被改写就全清 surfaced：压缩成功、`/compact`、`/clear` 三处
  统一调一次 `surfaced.clear()`（`run_agent` 加一个注入回调，装配层接线）。
  代价：压缩后那几篇可能被再召回一次（多花一次注入的 token），
  但语义诚实——「已经在上下文里」在压缩后就是假的。
- 候选 B·只清被切掉的那些（精确）：`surfaced` 从 set 升成 name→注入时的消息
  下标，压缩后只删下标 < cut 的。更省 token，但要给 RecallState 加一层簿记，
  且下标在压缩重建后会漂（要跟着 ledger 走），复杂度明显高一档。
- 候选 C·暂不改，只把 `/clear` 那半登记进 TODO。
