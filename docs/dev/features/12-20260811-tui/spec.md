# spec：12-tui —— scrollback + dock 的终端 UI

档案：[README.md](README.md) ／ 状态：已拍板 ／ 分支：`feat/12-tui`
拍板问答完整存档见档案「候选方案与确认」节，本文件不复述取舍过程，只写**要做成什么样**。

## 一句话

把 `modes/interactive.py` 的纯 REPL 换成 **「上面是终端的 scrollback、下面是 pai 接管的
dock」** 这一种形态，从而让「一个输入流两个消费者」「干活时能打字」「模式看得见也切得动」
这三件在纯 REPL 里结构上做不出来的事有个家。

```
┌ 终端 scrollback（终端拥有，pai 打完就不再碰）───────────┐
│ › 读一下 README                                          │
│ 🤖 好的，我先看看……                                      │
│ 🔧 read_file: README.md                                  │
└──────────────────────────────────────────────────────────┘
╭ dock（pai 接管，逐帧重绘，高度随内容变）─────────────────╮
│ ◐ read_file: a.py │ ◐ bash: npm test                     │  活动区（并发可见）
│ ⏳ 已排队 1 条                                            │  队列区
│ › 用户在这里打字█                                         │  输入行（硬件光标=IME 锚点）
│ acceptEdits · shift+tab 切换 · 2 个请求在等               │  状态行
╰──────────────────────────────────────────────────────────╯
```

## 已经拍过板、本轮不再议的前提

1. roadmap 阶段 2 的四条 TUI 设计原则（`Component.render(width)` 纯函数契约 /
   只做 main-screen 不假装 sticky / CURSOR_MARKER 零宽标记定位硬件光标 / 差量重绘后置）。
2. 本档案四问的结论：方案 A、plan 不进本轮、对话框照抄 CC 抑制语义、干活时输入走 followUp。
3. **不引入任何第三方 TUI 库**，也不抄 pi/CC 的代码（AGENTS.md 项目定位约束）。

## 目标（做什么）

### G1 · TUI 内核

- `Component` 契约：`render(width: int) -> list[str]` **纯函数**（不持终端句柄、不写 IO），
  外加 `invalidate() -> None`。理由与 pi 的四成员契约对照见
  [K pi-tui-main-screen 第二节](../../../../knowledge/source-walks/pi-tui-main-screen.md)。
- `Container`：按顺序拼接子组件的行，`invalidate()` 递归下发。
- **dock 渲染器**：把根组件渲染成行数组，用相对光标移动（`CSI nA/nB`）+ `CSI 2K` 清行
  重绘 dock 区，整段写入包在同步输出 `\x1b[?2026h` / `\x1b[?2026l` 里。
  **dock 之上的行一律不碰**——那是 scrollback，够不着也不该够。
- **差量重绘不做**（原则 4）：dock 每帧整体重画。dock 高度是个位数，代价可接受；
  真需要优化时再说，且必须先有数字（AGENTS.md `perf` 的判据）。

### G2 · 行编辑器（自写，替掉 readline）

- 编辑：插入 / 退格 / Delete、左右移动、Home/End、按词左右跳、Ctrl+U / Ctrl+K / Ctrl+W。
- 历史：↑/↓ 翻 05 已交付的历史文件（按 cwd 分文件、连续重复只记一条，语义不变）。
- **中文宽度感知**：光标列用 `display_width` 算，不用字符数。
- **CURSOR_MARKER**：编辑器在光标处吐一个零宽标记，渲染器在合成后的行里找到它、
  算出可见列、剥掉标记，再把**硬件光标**摆过去。这是中文 IME 候选框位置正确的唯一解法。
- bracketed paste（`\x1b[200~` … `\x1b[201~`）：粘贴内容整体插入，不逐字符触发重绘。
- 续行：保留现有「行尾 `\`」语义，不做多行编辑器。

### G3 · 输入归属仲裁（本次的核心）

- **一个仲裁函数**决定此刻谁拥有输入，消费者只有一个 `is_active` 开关——
  替掉今天「asker 与主循环共用一个阻塞 reader，谁先 `read()` 谁拿到」。
- 抑制语义照抄 CC（[K cc-input-ownership 第一节](../../../../knowledge/source-walks/cc-input-ownership-and-modes.md)）：
  - 输入框**非空** → 压住所有权限框/提问框；
  - 距最后一次按键满 **1500ms** → 放行队首对话框；
  - 被压期间在状态行**显式提示**「N 个请求在等」，**不许静默**；
  - 用户主动唤出的对话框不受压制。
- **1500ms 是抄来的常数**，常量旁必须写明来源与它依赖的前提
  （TODO「给照抄来的常数建一条检查习惯」）。

### G4 · 对话框

- 权限 `ask` 与 `AskUserQuestion` 走**同一套**对话框组件（今天已经在 `gate.py` 合流）。
- Esc 取消：权限框 = 拒绝本次调用；提问框 = 取消回答。
- 验收铁证：提问期间敲 `!echo 我是命令` 与 `/status`，**必须**当成命令执行，
  不得被当成对问题的回答（这正是 08 遗留记录的那次真实事故）。

### G5 · 权限模式切换

- `/mode`：无参列出四态与当前态；带参切换。
- `shift+tab`（`\x1b[Z`）轮转：`default → acceptEdits → bypassPermissions（可用时）→ default`。
  - **`dontAsk` 不进轮转环**——它与「无真人」合流（D#53），不该出现在给真人按的快捷键上。
    CC 的 `dontAsk` 同样「尚未暴露在 UI 环里」。
  - **给 `plan` 留位**：轮转表写成数据而非 if 链，plan 单独立项后加一行即可。
- 状态行常驻显示当前模式；`/status` 与 `/permissions` 也要显示（关掉 TODO 里
  「`/permissions` 不显示当前权限模式」那条小修）。
- **命令与快捷键都要有**：CC 明说组合键在部分终端不可靠，必须有不依赖组合键的路径。

### G6 · 干活期间的输入（steering 的落点）

- agent 干活时**继续读 stdin**，按键实时进 dock 输入框（反向对照已证：字符本来就在
  内核 tty 缓冲区里等着，见 [evidence 第 2 条](evidence/20260811-终端反向对照/说明.md)）。
- 回车 → 进 **followUp** 队列，dock 显示「已排队 N 条」，本轮结束后依次发出。
- steering 队列**保持现状**（结构在、注入点在、有假回调测试钉死位置），
  本轮不通电——拍板选的是 followUp。05 那条遗留因此**只关掉一半**，如实记。

### G7 · 并发可见

- dock 活动区里，同一批并发工具**各占一行**同时显示，各自独立结束。
- 这要求 `ToolStart`/`ToolEnd` 带上足以分辨「谁跑完了」的信息。
  feature 11 的取舍是「所有事件都在主线程发、`ToolEnd` 按原顺序交付」——
  **本轮不改线程模型**，若按原顺序交付不足以呈现并发，最小改动是给事件加时间戳
  （11 复盘质疑二本来就给了这个提示）。

### G8 · resize

- 装 `SIGWINCH`，**同步处理不去抖**，**同尺寸事件直接丢弃**（CC 的 `handleResize`
  两条注释都是实证性的：去抖会造成双重闪烁，终端一次操作常发 2+ 次事件）。
- 只重画 dock。scrollback 不碰、不清。
- 关掉 TODO「pai 对窗口 resize 完全无反应」与「状态行按事件而非按 resize 重算」两条。

### G9 · 退化与兜底

- **非 tty 闸门**：`sys.stdout.isatty()` 为假就**整个不进 TUI**，退回今天的行为
  （与 CC 同口径：判 stdout 不判 stdin）。顺带把「管道下仍打欢迎语与 `› ` 提示符」
  这条噪音一并处理。
- **主循环兜底**：任何逃逸异常都回到提示符（`EOFError` 除外——那是 Ctrl+D 正常退出）。
  TUI 化让这条从「体验」升级为「必须」：异常逃逸会把用户终端留在 raw mode / 光标隐藏。
- **终端状态无条件复原**：退出路径（正常/异常/信号）一律写回 disable 序列并显示光标。
  CC 的理由是「终端能力检测不可靠，无条件发，不支持的终端上是 no-op」。
- **主线程断言**：TUI 与信号处理器都要求跑在主线程。`_install_sigint` 今天在非主线程
  会静默失效（05 遗留）——本轮的结论是**不把 REPL 挪到子线程**，并加一条显式断言/告警
  让这条假设**被违反时会响**，而不是等中断静默失效。
- **超宽 fail-loud**：渲染出的行宽超过终端宽度即报错并指认组件，不放任它折行
  （折行会让所有相对光标移动错位，症状是满屏乱跳而非某处显示不全）。
  pi 为此专门 dump + throw；pai 做等价的最小版。

## 非目标（明确不做，写下来是为了以后不吵）

| 不做 | 理由 |
|---|---|
| alt-screen、主题系统、鼠标 | roadmap 阶段 2 范围原文排除 |
| transcript 内滚动 / 搜索（CC 的 Ctrl+O） | 方案 A 结构上做不到；要做得走方案 B |
| **plan 模式的语义** | 本档案问 2 改判：单独立项，本轮只留位 |
| `Ctrl+R` 增量历史搜索 | readline 白送的，自写不便宜。**这是一处已知功能回退**，必须登记 TODO |
| 多行编辑器 | 保留现有「行尾 `\`」续行语义 |
| 差量重绘 | 原则 4：先正确后快，且 `perf` 必须先有数字 |
| 改线程模型 / 改事件线程语义 | 本轮结论是**主线程持有一切**；并发工具留在线程池不变 |
| 会话恢复 `/resume` | 05 spec 非目标，要先有会话树 |

## 验收标准（怎么算做完）

**行为**

1. 模型调 `ask_user_question` 期间，输入 `!echo 我是命令` 与 `/status`
   **被当成命令执行**，不进答案——08 遗留那次事故的反例。
2. 有待决权限请求时，用户正在打字则对话框不弹、状态行提示「N 个请求在等」；
   停手约 1500ms 后自动弹出。
3. `shift+tab` 与 `/mode` 都能切模式；`dontAsk` 不出现在轮转里；状态行实时反映当前模式。
4. agent 干活时打字可见于 dock 输入框；回车后显示「已排队」，本轮结束后发出。
5. 同一批并发工具在 dock 里**同时**可见，不是按顺序一个个冒出来。
6. 改变终端宽度后 dock 立刻按新宽度重画，输入行不错位，**scrollback 不被清空**。
7. `pai | cat` 与 `pai < /dev/null` 的行为与今天一致（不吐转义符、不进 TUI）。
8. 任意一条路径抛异常，会话不死、回到提示符，且终端不残留 raw mode / 隐藏光标。

**验证**

9. `./test.sh` 全绿，**新增测试不少于 40 条**（下限不是精确值——
   feature 09 复盘的教训：把计划估算当成应达成的事实，会制造必然失败的对账）。
10. 至少一条测试拿**真实会话轨迹**当输入（AGENTS.md 测试规约）。
11. **手工验收**：中文 IME 候选框贴着输入光标（这条离线测不出，必须真人在真终端里看，
    基准线已记在 [evidence 手工清单](evidence/20260811-终端反向对照/手工清单.md)）。

## 已知风险

1. **自写行编辑器是本轮最大的成本与最大的回退面**。readline 白送的东西（Ctrl+R、
   词跳的边界细节、libedit 与 GNU readline 的差异）会以「用户觉得变难用了」的形式暴露。
   缓解：编辑器是纯函数组件（收按键、吐新状态），可离线密集测；Ctrl+R 明确列为回退并登记。
2. **raw mode 下的按键解析是长尾**。方向键、Home/End、shift+tab 在不同终端序列不同。
   缓解：只支持一组主流序列，未识别的按键**丢弃而非塞进输入框**，并留一条调试开关。
3. **IME 只能靠人验**。CURSOR_MARKER 的机制可以单测（标记被正确找到、列号算对、被剥掉），
   但「候选框真的贴着光标」测不出来。诚实边界写进验收标准第 11 条。
4. **dock 高度变化时的行为**是本方案最容易出错的地方：dock 变矮时上方多出来的行
   已经属于 scrollback，清不掉。缓解：dock 变矮时先把多余行清空再收缩，且这条要有测试。
