## 从这张图改了 plan 的四处

原 plan 写得不够，按图补的（见 [plan.md](../../plan.md) T1/T6/T7）：

1. `commit(lines)` 这个操作原先根本没写。 图里 `› 继续`、`● 写 plan 前…`
   都已经离开 dock、进了 scrollback。这是 dock 与 scrollback 之间唯一的通道，
   也是这类实现最容易出错的地方（清 dock 与打印的顺序反了就会叠影）。
   已补进 T1 并配两条注入反证。
2. 并发的呈现形态。 原 plan 写「一工具一行」，图里 CC 是
   按动作聚合计数（`Reading 1 file, running 1 shell command…`）+ 明细行。
   两者都满足「并发可见」，但聚合形态在工具多时不会把 dock 撑高。改成照 CC。
3. 状态行带转圈 + 已用时 + 本轮 token（`(16s · ↓ 536 tokens)`）。
   原 plan 的状态行只有权限模式与待决请求数。pai 已经有 usage 与预算数据，
   这是零新增数据源的一处白捡收益。
4. turn 结束要 commit 一行摘要（图里的 `✳ Cooked for 6m 48s`），
   而不是把活动区清空了事——否则一轮跑完屏幕上什么痕迹都不留。
