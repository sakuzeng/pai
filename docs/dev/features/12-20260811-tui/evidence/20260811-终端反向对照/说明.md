# 反向对照：在真终端里跑现有 pai，看文档与源码读不出来的东西

日期：2026-08-11 ／ 归属：[features/12-tui](../../README.md) 第 2 步（前置精读）

**为什么做**：feature 09 的教训是「精读覆盖了文档每一节，却漏掉一整层机制」；
feature 11 照此加了一次反向对照，一次撞出三条文档读不出来的事实，
其中一条直接决定了核心代码怎么写。TUI 的反向对照不是打 API，是**在真终端里跑**。

**没有花钱**：全部探针都不提交 prompt。唯一一次意外——p4 初版让
「干活时打的字」带了回车，`!sleep 3` 结束后被当作新一行提交给了模型，
发现后立即 kill；改成不带回车重跑，结论不受影响。**这次意外如实留档。**

## 怎么跑的

`probe.py` 用 `pty.fork()` 起一个**真 pty**（`isatty()` 为真、`TIOCSWINSZ` 可改窗口、
`\x03` 走行规程变 SIGINT），父进程当「终端」抓原始字节。
脚本在 `pai_playground/tui-probe/` 里，本目录是入库副本。

```
probe.py            公共：spawn / set_winsize / drain
p1_startup.py       启动、/help、/exit
p2b.py + sl_driver.py  状态行：\r 刷新、中文宽度、中途 resize
p3_signals.py       Ctrl+C 两级
p4_resize_typing.py resize 时的输入行、干活期间打字去了哪、Ctrl+D
```

## 诚实边界：三项我**没有**观测，留给人工

本机没有 tmux，也没装 pyte——**我是 pty 的另一端，不是终端模拟器**，
看得见字节看不见屏幕。以下三项的结论只能由真人在真终端里看：

1. **中文 IME 候选框位置**（要真的用输入法打字）
2. **`\r` 刷新的视觉残留**（要看到折行后 `\r` 只回到最后一个视觉行行首）
3. **真实拖动窗口的 resize 表现**（`TIOCSWINSZ` 只是程序化改尺寸，
   跟窗口管理器连发多次事件不完全等价）

手工清单见本目录 [手工清单.md](手工清单.md)。

## 撞出来的事实

### 1. pai 现在对窗口 resize **一个字节都不发**（与预期不符）

`p4_resize_typing.py`：在提示符处打了半行中文（未回车），把窗口从 80 列改到 30 列、
再改到 100 列，pai 侧输出**完全为空**：

```
===== D0 打了半行（未回车） =====   '半行中文没回车'
===== D resize 80→30 列 =====      ''
===== E resize 30→100 列 =====     ''
```

pai 没装 `SIGWINCH` 处理器，readline 也没有重绘。后果：窗口变窄时，
终端按新宽度重排已经打出的字符，而 readline 内部的列计数还是老的——
光标位置与实际显示会错位。

**对照**：pi 宽度一变就全量重绘（`tui-main-screen.ts:236`），
CC 的 `handleResize` 刻意不去抖、同尺寸事件直接丢
（两家都当强事件，见两篇笔记）。**pai 是三家里唯一完全不处理的。**

### 2. 「干活时打的字」没丢，它在内核 tty 缓冲区里等着

`p4`：`!sleep 3` 执行期间输入「干活时打的字」（不带回车），
3 秒后 shell 命令结束，这些字符**原样出现在下一个提示符上**：

```
===== F !sleep 3 期间打字（无回车） =====
'› !sleep 3\r\n(命令没有输出，退出码 0)\r\n› 干活时打的字'
```

**这条改变了 steering 那条遗留的定性**。TODO 里记的是
「阻塞的 `input()` 拿不到『agent 干活时打字』」——字符其实一直都在，
是**行规程替我们缓冲住了**，pai 只是在干活期间没有去读。
所以 steering 需要的**不一定**是「独立输入线程」，
在干活期间对 stdin 做非阻塞读/`select` 就能取到。
（注意：这只覆盖「按了键」，不覆盖「按键要立即改变界面」。）

### 3. 两级 Ctrl+C 在空闲态就会直接退出

`p3_signals.py`：

```
B 空闲时第一次 Ctrl+C → '(输入已清空，再按一次 Ctrl+C 退出)\r\n› '
C 紧接第二次 Ctrl+C   → '再见。\r\n'   （进程退出）
```

行为正确，但**空闲且输入为空时第一次 Ctrl+C 也算「一级」**——
CC 的第一级语义是「中断当前操作」，没操作可中断时按两下就退出。
是否要区分「空闲态的 Ctrl+C 不计数」是个可议的取舍，记在这里。

### 4. 状态行的宽度是**按事件重算**的，不是按 resize 重算

`p2b.py` + `sl_driver.py`（80 列起，1.2s 后改 40 列）：

```
[BEFORE] cols=80 rendered_width=79
[AFTER-RESIZE] cols=40 rendered_width=39
```

`StatusLinePrinter.handle()` 每次都调 `self._width()` 重取列数，所以
**下一个工具事件到来时**会按新宽度渲染。但在那之前，屏幕上还留着按 80 列
渲染的那一行——窗口缩到 40 列后它会被终端折成两行，而后续的 `\r\x1b[K`
**只清得掉最后一个视觉行**。这正是「`\r` 与 scrollback」那条要观察的失效形态，
视觉部分待人工确认（手工清单第 2 项）。

顺带确认：渲染宽度恒为 `cols - 1`，刻意空出最后一列，避开自动折行。

### 5. 宽度守卫是结实的：1..120 列 × 中文/emoji/ASCII 混合，零越界

```python
for w in range(1, 121):
    for n in range(1, 5):
        assert display_width(render_tool_line(evs, w)) <= w
# 超宽用例数： 0
# display_width('🎉') = 2   display_width('中') = 2
```

pi 为「组件忘了截断」准备了 fail-loud（超宽即 dump + throw，
`tui-main-screen.ts:413`）。pai 目前**靠的是每个渲染函数自觉**，
没有任何断言挡住将来新增的组件。便宜的仿制品，值得做。

### 6. 非 tty 下不吐转义符，但**照样打欢迎语与提示符**

```
$ printf '/help\n/exit\n' | pai | cat -v
pai 交互模式。/help 看命令，Ctrl+D 退出。
› 可用命令：
...
› 再见。
```

没有 `\r`、没有 ANSI（退化正确），但 `› ` 提示符与欢迎语进了管道。
CC 的口径是 **stdout 不是 tty 就整个走非交互路径**（`main.tsx`）。
与 feature 11 遗留「`once` 的输出形态变了，而 once 是给脚本用的模式」是同一类账。
