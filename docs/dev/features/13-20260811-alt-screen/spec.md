# spec：13-alt-screen —— pai 拿下整个屏幕

<!-- superpowers brainstorming 的产物：六问拍板后的共识落盘。拍板原文存档在 README「确认」节。 -->

## 一句话

真 tty 下 `pai` 进**备用屏**（DECSET 1049）：整屏归 pai——上面是**可键盘滚动的
transcript 视口**，下面是 12 交付的 dock；退出时把屏幕**原样还给 shell**，
只在主屏上留一行「会话已存在哪」。**本轮不接管鼠标**。

## 背景与问题

用户真跑 feature 12 之后连提三条：工具结果能点、transcript 能滚、
「感觉是新开了一个窗口而不是在终端下继续这种」。追下去发现底下是同一个约束——
**谁拥有屏幕**。12 交付的方案 A 只接管屏幕底部的 dock，内容一打出去就归终端所有，
pai 再也够不着：不能重画、不能高亮、更不能做命中测试。所以「点击」**不是没做，是做不到**。

## 已经拍过板、本轮不再议的前提

1. **形态是「乙」**：常驻 alt + 键盘滚动。**不接管鼠标**（点击单独立项）。
2. **默认进 alt**，给一个关掉的开关，落 `.pai/settings.json`（不加环境变量）。
3. **退出时不回吐完整 transcript**，只打一行提示（对齐 CC 的 `printResumeHint()`）；
   `--resume` 单独立项。
4. **本轮不做搜索**（需求第 2 条只做「滚动」那一半）。
5. **原则 2 的处置**：作废的只是 pai 自己加的「只做 main-screen 模式」这半句；
   pi 那句「别在 main-screen 里*假装* sticky 语义」照旧成立，roadmap 就地留痕。
6. **实测结论是硬约束**（[evidence](evidence/20260811-alt-screen反向对照/说明.md)）：
   绝不重发 `?1049h`、绝不 `2J` 清屏、resize 必须全量重绘、能力探测不许问终端。

## 目标（做什么）

### G1 · 扩终端模拟器 `screen.py`，**第一个做**

`src/pai/tui/screen.py` 现在把私有 CSI 当无操作，且不认 `H`(CUP) 与 `J`(ED)，
strict 模式下直接抛。**不先扩它，alt-screen 一上线，`PAI_TUI_RECORD` 回放出来的图就是错的、
`tests/test_e2e_tui.py` 的 5 条全部失效**——feature 14/15 刚建起来的「让 AI 自己看得见
界面」会退回到「让用户截图」。

要加：
- `?1049h/l`：**两块缓冲区**（主屏/备用屏各一份格子 + 各自光标），切换时存/复光标，
  进备用屏时清空它；**已在备用屏时再发 `?1049h` 同样清空**（照实测，不是 no-op）。
- `H`(CUP，1-indexed 行列)、`J`(ED：`2`=整屏、`0`=到屏尾、`1`=到屏首)。
- `?7l/h`（自动折行开关）：关掉时超宽内容**在右边界截断**而不是折到下一行。
- `?25h/l` 继续当无操作（光标可见性不影响内容）。

### G2 · Transcript：一份**按宽度重新渲染**的文档

今天 `app.commit(lines)` 收的是**已经按当时宽度排好的行**。alt 屏下窗口一变宽变窄，
这些行就是错的——所以 transcript 不能存行，要存**能按宽度重渲染的条目**：

```
TranscriptEntry.render(width) -> list[str]      # 与 Component 同构的纯函数契约
```

- 条目种类就是今天 `commit()` 的那些调用点：logo 定格、用户输入色带、模型答案、
  工具行、事件摘要、`^O` 展开的整段输出、错误行。
  **做法是把现有的 `_answer_lines` / `_tool_lines` / `theme.band` 从「commit 时调用」
  推迟到「渲染帧时调用」**，渲染逻辑一行不改，只改调用时机。
- 每个条目按 `(内容, 宽度)` **缓存**自己的行（照 pi：叶子自己持有缓存，
  框架层**不许**再加第二层——失效语义归组件自己所有）。
- `total_lines(width)`、`slice(width, top, height)` 供视口取用。

### G3 · 滚动状态机（照 pi 的 `ScrollView`）

- `scroll_top` / `following_end` / `viewport_height`。
- **follow-end 语义**：起始跟随；内容长高时自动贴底；**手动往上滚就关掉跟随**；
  滚回底部或按 End 重新打开跟随。
- 视口高度变化（resize、dock 变高变矮）时**保住 `scroll_top`**，除非在跟随态。
- 键位：`PgUp`/`PgDn`（翻一屏，**留 4 行重叠**，照 pi 的 `PAGE_SCROLL_OVERLAP`）、
  `Home`=顶、`End`=底并恢复跟随。`keys.py` 需补 `\x1b[5~` / `\x1b[6~` 的解析。
- 键位只在**输入框为空**时生效……**不**：输入框里 PgUp/PgDn 本来就没有编辑含义，
  直接给滚动；`Home`/`End` 今天是行首/行尾（编辑器已实现），**冲突**——
  裁决：`Home`/`End` 归编辑器不变，滚到顶/底用 `Ctrl+Home`/`Ctrl+End`（照 CC）。

### G4 · 全屏帧渲染器（替掉 `DockRenderer` 在 alt 下的角色）

```
每帧：transcript.slice(width, scroll_top, viewport_h) + dock.render(width)
      → 补齐/裁剪到正好 terminal.rows 行
      → 与上一帧逐行比，只重写变了的行：CSI <row>;1H + CSI 2K + 内容
      → 摆硬件光标（CURSOR_MARKER，沿用 12 的提取逻辑）或藏起来
      → 整帧包在 CSI ?2026h/l 里
```

- **绝不发 `2J`**（CC：先擦会让屏幕在整个渲染耗时里全黑）；
  **绝不重发 `?1049h`**（实测：会清屏闪白）。首帧与 resize 后走「每一行都写」而不是清屏。
- 行宽保护：每行渲染后按 `display_width` 截到 `width`（配合 G1 的 `?7l`，双保险）。
- dock 的高度由内容决定，transcript 视口高 = `rows - dock 高`，**最少 1 行**。

### G5 · 进出备用屏与异常路径

- 进：`?1049h` + `?7l`(关折行) + `2J` + `H` + 藏光标。**进 alt 必须早于第一帧**
  （CC 的教训：顺序反了，那一帧留在主屏上，**退出后**才作为脏东西暴露）。
- 出：显示光标 + `?7h` + `?1049l`，**无条件**（正常退出 / `Ctrl+D` / 异常 / 信号）。
  沿用 `terminal.py` 现有的「退出无条件复原」，把 alt 一并纳入。
- 出来之后在**主屏**打一行：`会话已存 ~/.pai/projects/<slug>/sessions/<id>.jsonl（N 轮）`。
  **不打 `--resume` 的用法**——它还不存在，提示不存在的命令比不提示更糟。
- resize：`SIGWINCH` → 重算视口 → **全量重绘**（每个格子都写，不清屏）。
  沿用 12 的「同尺寸事件丢弃」。

### G6 · 开关与退化

- `.pai/settings.json` 新增顶层 `"tui": {"altScreen": true}`，两层合并（用户级 + 项目级），
  与权限层同一套加载路径。默认 `true`。
- 关掉时 → 完全走 12 交付的 main-screen dock 路径，**一个字节的 alt 序列都不发**。
- 非 tty（`pai | cat`、CI、注入 reader）→ 闸门在 `use_tui()`，**行为一个字不变**。

### G7 · 滚动位置要**看得见**

用户往上滚之后，新内容还在来，但屏幕不动——不给指示的话与「卡死了」无法区分
（12 复盘质疑二同款病）。状态行右侧显示：
- 跟随态：不显示额外东西
- 已上滚：`已上滚 N 行`；若期间有新内容到达，追加 `· 有新内容`

## 非目标（明确不做，写下来是为了以后不吵）

- **鼠标**：不发任何 `?1000/1002/1003/1006`。于是终端原生的拖选复制与 `Cmd+F`
  **照旧能用**——这是本轮刻意保住的东西，不是遗漏。
- **点击工具结果展开/折叠**：需求第 1 条，单独立项。本轮建的是它的地基
  （每帧知道每个条目画在哪几行）。
- **transcript 内搜索**：需求第 2 条的另一半，下一轮。
- **`--resume`**：单独立项，紧接着做。
- 虚拟滚动/差量布局等性能优化（`perf` 得先有数字）；`HStack`/侧边栏/滚动条；
  图片协议；自研选区与 OSC 52；tmux -CC 探测；Kitty 键盘协议。
- 不动 `once` 与非 tty 路径的任何行为。

## 视觉层

（12 复盘追记的教训：spec 只写功能不写视觉，交付后第一眼「没有 TUI 呀」，
随后四轮视觉修正全靠截图往返。）

```
┌──────────────────────────────────────────────┐ ← 整屏归 pai（备用屏）
│ pai logo（定格那份，滚上去就没了）           │
│                                              │
│ ▌你说的话（整行色带，theme.USER_BG）         │  transcript 视口
│ 模型的回答……                                 │  高 = rows − dock 高
│   工具行（折叠态，青蓝）                      │  往上滚看历史
│                                              │
├──────────────────────────────────────────────┤ ← dock.rule()，分隔线
│ 活动区：按动作聚合的计数                      │
│ 队列区：待发消息                              │  dock（12 交付的原样搬过来，
│ › 输入行 或 对话框                            │   高度按内容，贴在屏幕底部）
│ 状态行  转圈 已用时 token 模式 待决  已上滚 N 行 │
└──────────────────────────────────────────────┘
```

- **配色沿用 `theme.py`**，不新增颜色。字形**不用 emoji**（D#63）。
- 分隔线用 dock 现成的 `rule()`，不加第二种分隔样式。
- **层级**：transcript 是「过去」（滚上去就静止），dock 是「现在」（每帧可变）。
  这条决定了一个视觉规矩：**dock 里的东西不许往 transcript 里漏**，反之亦然。
- 滚动指示只在状态行右侧，用文字不用符号画滚动条（滚动条是非目标）。
- 空会话时：logo 定格那份在最上面，视口其余是空的（不填充装饰）。

## 验收标准（怎么算做完）

数字一律写**下限**（12 复盘：把计划估算当成应达成的事实，制造了必然失败的对账）。

1. `./test.sh` 全绿，新增测试 **≥ 45** 条。
2. `screen.py` 认得 `?1049h/l`、`H`、`J`、`?7l/h`，且**重发 `?1049h` 会清空备用屏**
   （照实测钉一条测试）；主屏内容在切回后**逐字还原**。
3. Transcript 按宽度重渲染：同一条目在 80 列与 40 列下行数不同，
   且**改宽度后取到的是新宽度的行**（缓存不许把旧宽度的结果发出来）。
4. 滚动状态机：跟随态下 append 自动贴底；手动上滚后 append **不移动视口**；
   按 `Ctrl+End` 恢复跟随；视口变高变矮时非跟随态的 `scroll_top` 不变。
5. 全屏渲染器：只重写变了的行（**注入反证**：把 diff 改成全量，断言写出的字节数变多）；
   输出里**不含** `2J`、不含第二个 `?1049h`（这两条各钉一条测试）。
6. 进出：进 alt 的序列**早于**第一帧内容；异常抛出后仍复原（`?1049l` + `?7h` + 显示光标）。
7. resize：SIGWINCH 后每一行都被重写，且**没有** `2J`。
8. 开关：`settings.json` 里 `tui.altScreen=false` 时输出中**没有任何** `?1049`。
9. 非 tty 下行为与今天**逐字节一致**（拿现有 e2e 断言兜住）。
10. **e2e**：真 pty + 假 provider 跑完整一回合，回放后断言
    ①屏幕上有模型的回答 ②dock 在最底部 ③上滚后 dock 仍在原位而 transcript 变了。
    每条 e2e 配**一条能还原原 bug 的注入反证**（feature 15 的教训：不红的测试等于没有）。
11. 交付前反向对照：在 iTerm2 与 Terminal.app 各跑一个完整真实回合，
    并把 evidence 的[手工清单](evidence/20260811-alt-screen反向对照/手工清单.md)走一遍。

## 已知风险

1. **崩溃/被 kill -9 会把用户留在空的备用屏里**（main-screen 下最坏只是留个乱 dock）。
   缓解：`try/finally` + `atexit` + 信号处理；**测不到 `kill -9`，如实声明**。
2. **`vim` 这类外部程序退出时的 rmcup 会把 pai 也踢回主屏**（CC 注释点名）。
   pai 今天的 `bash` 工具就可能跑到这类程序。本轮**不做自愈**（自愈要么清屏要么没法探测），
   如实登记为遗留。
3. **长会话的内存**：transcript 全量持有条目。文本很便宜，但没有上限。
   本轮不设上限，登记为遗留（要设也该等有数字）。
4. **两条主循环变三条渲染路径**（tty+alt / tty+main / 非 tty），
   12 复盘质疑四那笔账加重。缓解：alt 与 main 共用同一份 `Dock` 与组件树，
   只有「帧怎么写给终端」这一层不同。
5. **退出后历史只剩 JSONL**，`--resume` 落地前有缺口——已在拍板时接受，登记 TODO。
