# spec：16-mouse-and-selection —— pai 接管鼠标

<!-- superpowers brainstorming 的产物：四问拍板后的共识落盘。拍板原文存档在 README「确认」节。 -->

## 一句话

备用屏里 **pai 接管鼠标**：滚轮滚自己的 transcript、拖选高亮并复制、点击工具结果展开/折叠。

## 背景与问题

feature 13 交付后用户第一次真跑就撞到：**往上滚看到的是自己之前几次运行留下的旧内容**。
根因是 pai 一个鼠标上报序列都不发，滚轮**穿透**给终端，而 iTerm2 在备用屏里
把它解释成「回看主屏 scrollback」。CC 之所以不这样，只因为多发了一串
`\x1b[?1000h?1002h?1003h?1006h`——**差别不在谁滚得动，在事件归谁**。

## 已经拍过板、本轮不再议的前提

1. **一次做到位**：滚轮 + 自写选区（问 1）。
2. **发 `1003`**，照抄 CC（问 2）。
   ⚠️ 实测附注：本机 iTerm2 上 `1002` 与 `1003` **观测不到差别**（纯移动指针两段都是 0 条），
   所以 1003 在这里**买不到 hover**。代码注释必须写明这一点，
   免得后来者以为 hover 是现成的。
3. **剪贴板 `pbcopy` 为主、OSC 52 兜底**（问 3）。
   ⚠️ 实测：**OSC 52 在本机 iTerm2 上写不进剪贴板**（BEL/ST 两种结尾都试，静默失败）。
   所以顺序是「本地系统剪贴板优先」，不是 pi 那样只发 OSC 52。
4. **点击展开进本轮**（问 4）。单击与选区起点的冲突照 CC 解：**没拖动才算点击**。
5. 只在**备用屏**下启用。main-screen（`tui.altScreen: false`）与非 tty 一个鼠标序列都不发。

## 实测数据（本轮设计的直接输入）

见 [evidence](evidence/20260811-鼠标与剪贴板/说明.md)。三条决定实现形态的：

| 实测 | 对实现的约束 |
|---|---|
| **一次滚动手势 = 上百条事件**（6 秒 142 条，触控板惯性尤甚） | 一批输入里的 wheel **必须累加成一个 delta、只重绘一次** |
| **拖动每跨一格一条**（153 条 / 148 个不同坐标） | 每条都携带新信息（焦点移到哪），**不能合并**；但重绘要合并 |
| **OSC 52 静默失败** | 复制不能只靠它；且**失败不可探测**，要有可见反馈 |

## 目标（做什么）

### G1 · 鼠标上报的进出，绑在备用屏的生命周期上

- 进：`\x1b[?1000h?1002h?1003h?1006h`，跟在 `?1049h` 的序言后面（同一次写入）。
- 出：**先关鼠标再退备用屏**（照 CC 的 `gracefulShutdown`：关鼠标要给终端一个往返的时间，
  否则事件在恢复 cooked 模式期间到达，会**回显到屏幕上或漏进 shell**）。
- 异常/信号路径同样复原（沿用 `TerminalSession.stop()` 的无条件复原）。
- 开关：`.pai/settings.json` 的 `tui.mouse`（默认 `true`）。关掉 = 回到 13 的行为。

### G2 · SGR 1006 解析进 `keys.py`

鼠标序列与按键走同一条字节流、**同样会被 `os.read` 拆包**，所以复用
`KeyDecoder` 已有的分片状态机，而不是另起一个解析器。

- `\x1b[<按钮;列;行M`（按下/拖动/滚轮）与 `…m`（松开），列行 **1-based**，内部转 0-based。
- 按钮位：`&3` 取键（0=左）、`|32` 拖动、`|64` 滚轮（`&3`：0=上、1=下）。
- 吐 `Key("mouse", …)` 携带一个 `MouseEvent`（`tui/mouse.py` 里的 frozen dataclass）。
- **不认识的鼠标扩展（1015/1016 编码）一律丢弃**，不猜。

### G3 · 事件合并（本轮唯一由实测倒逼出来的设计）

`driver.poll` 一次 `os.read(4096)` → `app.feed` 处理整批 → **末尾只 refresh 一次**。
这条 feature 12 的既有结构已经吃掉了大部分洪水，本轮要做的是**把它钉死、并补上累加**：

- 一批里的 wheel 事件**累加成一个 delta**，只调一次 `scroll_by`；
- 拖动事件**只保留最后一个**（选区焦点是「现在在哪」，中间过程无意义）；
- 按下/松开**不许合并**（它们是状态跃迁）；
- **验收断言：喂 142 条 wheel 只产生 1 帧**（拿实测数字当测试输入）。

### G4 · 滚轮滚 transcript

- 向上/向下各滚 `WHEEL_LINES = 3` 行（常量旁写明「凭手感定，无实测依据」）。
- 复用 feature 13 的 `ScrollState`：滚到底自动恢复跟随、往上滚关闭跟随。
- 指针在 dock 上滚也滚 transcript（pai 只有一个滚动区；照 pi 的
  「no hit ancestor consumes the delta → 给 primary」）。

### G5 · 选区

**pai 可以比 CC 简单得多，因为它持有整份文档**：

> **选区锚在 transcript 的逻辑行号上，不是屏幕行号。**

于是 CC 那套 `scrolledOffAbove/Below` + 平行的软折行位图（滚出视口的行要另存）
**整块不需要**——滚动时选区天然跟着内容走，取文本直接从 transcript 取。

- 状态：`anchor(行,列)` / `focus(行,列)` / `dragging`，归一化后 start ≤ end。
- **裸点击不产生选区**（照 CC：与锚点同格的第一次移动不算数），否则单击会
  清掉剪贴板、也会与 G7 的点击展开打架。
- 高亮：渲染帧时把选中区间套上反显（`\x1b[7m` … `\x1b[27m`），
  **按显示列切片**（复用 `theme.wrap` 那套 ANSI 感知的列计算，不许按字符数切）。
- 取文本：按逻辑行取、逐行 `rstrip`、`\n` 连接，**剥掉所有转义序列**。
- **选区只在 transcript 区域**：按在 dock 上不启动选区（本轮非目标，见下）。
- Esc 或下一次按下清除选区。

### G6 · 复制：双路径 + **可见反馈**

松开鼠标时若存在非空选区，立即复制（copy-on-select，照 CC 默认）：

1. **本地优先系统剪贴板**：macOS `pbcopy`；Linux 按序试 `wl-copy` / `xclip` / `xsel`。
   看**退出码**判成败。
2. **`SSH_CONNECTION` 有值、或本地路径全失败** → 发 OSC 52。
3. **OSC 52 无法确认成败**（实测会静默失败），所以：
   - 走系统剪贴板成功 → 状态行闪一句 `已复制 N 行`；
   - 只发了 OSC 52 → 闪 `已尝试复制（OSC 52）`，措辞上不许假装成功。

子进程调用**不许阻塞主循环**：给 0.5s 超时，超时即当失败走兜底。

### G7 · 点击工具结果展开/折叠

用户最早那句「我想这个 bash 和 bash 的结果能点」的落点。

- `Transcript` 增加「第 N 个可见行属于哪个条目」的映射（`slice` 时顺带返回 owner）。
  **这就是命中测试的全部**——pai 不需要 CC 的矩形树，因为它的布局是一维的（行）。
- 工具条目变成**有状态**的：折叠态渲染一行（现有形态），展开态渲染完整输出。
  缓存 key 要含展开状态（否则点了不变）。
- 点击落在工具条目的任意一行 → 切换该条目的展开态 → 重绘。
- **`^O` 保留**（13 交付的键盘展开），两者互不干扰。

### G8 · 退化与逃生口

- `tui.mouse: false` → 一个鼠标序列都不发，回到 13 的行为。
- 启动提示行补一句：`滚轮/拖选可用 · 需要终端原生选择时按住 Option 拖`
  （**Option 这条退路在 iTerm2 上有效，Terminal.app 未实测**——措辞要留余地）。
- tmux -CC 之类「alt+鼠标不可用」的组合**不做自动探测**（CC 为此 spawn 子进程问 tmux，
  pai 不做），出问题让用户关开关。

## 非目标（明确不做，写下来是为了以后不吵）

- **双击选词 / 三击选行**（CC 有；本轮只做字符级拖选）。
- **拖到边缘自动滚**（CC 有；本轮拖出视口就停在边界）。
- **dock 区域的选区**（只在 transcript 里选）。
- **hover 高亮**——实测本机 1003 报不出无按键移动，做不了。
- **块选/矩形选**、跨 `resize` 保持选区、选区跨 pai 与 shell。
- **OSC 8 超链接点击**、滚动条、图片。
- 不动 `once`、非 tty、main-screen 三条路径的任何行为。

## 视觉层

（12 复盘的教训：spec 只写功能不写视觉，交付后第一眼「没有 TUI 呀」。）

- **选中高亮**：反显（`\x1b[7m`），不新增颜色——选区要在任何配色下都看得出来，
  而反显是唯一不依赖主题的手段。
- **可展开的工具行**：折叠态末尾已有 `… 还有 N 行 · ^O 展开`，
  本轮改成 `… 还有 N 行 · 点击或 ^O 展开`；展开态末尾给 `· 点击收起`。
  **不加图标、不加下划线**（D#63 的字形约束照旧）。
- **复制反馈**：状态行右侧短暂显示 `已复制 N 行`，1.5 秒后消失
  （复用 dock 现有的状态行位置，不引入浮层）。
- **层级不变**：transcript 是过去、dock 是现在。选区高亮只出现在 transcript 区域。

## 验收标准（怎么算做完）

数字一律写**下限**。

1. `./test.sh` 全绿，新增测试 **≥ 40** 条。
2. 解析：按下/松开/拖动/滚轮四类各有测试；**序列被 `os.read` 拆成两半仍能拼回**；
   1015/1016 编码丢弃不崩。
3. **合并**：喂进 142 条 wheel（实测数字）**只产生 1 帧**；
   注入反证——去掉累加改成逐条 `scroll_by`+`draw`，该测试必须变红。
4. 滚轮：向上滚关闭跟随、滚到底恢复跟随（复用 13 的状态机，接线有测试）。
5. 选区：锚在**逻辑行**——选中一段后**滚动，选区仍框住同样的内容**（这条是 pai 相对 CC
   的简化点，必须钉死）；裸点击不产生选区；取文本剥净转义序列；中文按列切不切半个字。
6. 复制：系统剪贴板成功/失败/超时三条路径各有测试（子进程注入）；
   `SSH_CONNECTION` 有值时走 OSC 52；**OSC 52 路径的提示语不许说「已复制」**。
7. 点击：点工具行切换展开态；点空白处不炸；**展开态换宽度重渲染正确**（缓存 key 含展开态）。
8. 进出：鼠标使能跟在 `?1049h` 之后；**关鼠标早于 `?1049l`**；异常路径也复原。
9. 开关：`tui.mouse: false` 时输出里**没有任何 `?100` 鼠标序列**。
10. main-screen 与非 tty 行为**逐字节不变**（现有 e2e 兜住）。
11. **e2e**：真 pty 里把实测抓到的真实字节序列喂进去（按下→拖动→松开、以及 142 条 wheel），
    回放后断言屏幕上有高亮、dock 未动、剪贴板调用被触发。
    每条配一条能还原原 bug 的注入反证。
12. **交付前反向对照**：真 iTerm2 里真人跑一次——滚轮、拖选复制（**粘贴出来核对**）、
    点击展开；并补上 evidence 手工清单里「松开事件」与「1002 vs 1003」两条未观测项。

## 已知风险

1. **选区与点击共用左键**，判据是「有没有拖动」。实测里那次拖动**只有 1 条按下、
   0 条松开**（8 秒到了还按着）——说明真实操作里按下与松开可能相隔很久，
   状态机必须容忍「按下之后长时间没有松开」。
2. **触控板惯性滚动的事件洪水**已实测（142 条/6 秒）。合并做对了就没事，
   做错了是「滚一下卡半秒」——而离线测试里 wheel 是一次性喂进去的，**看不出卡**。
3. **OSC 52 静默失败**：远程场景下用户会以为复制了。措辞已在 G6 处理，但**无法根治**。
4. **拿走鼠标之后，跨 pai 与 shell 的选择不可能**（想同时选 pai 里和 pai 外的内容）。
   Option 拖是终端级逃生口，写进提示，但 Terminal.app 未实测。
5. **`kill -9` 后鼠标模式留在终端里**：与 13 那条「留在备用屏」同源，且更烦——
   shell 里鼠标会失灵。同样兜不住，如实登记。
