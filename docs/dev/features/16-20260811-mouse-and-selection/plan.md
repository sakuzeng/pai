**规矩**（AGENTS.md）：每个 task 先写测试跑红（**贴红的输出**），再写实现跑绿（**贴绿的数字**）。

## 动工前先摆平的三个结构问题

### ① `Key` 要能带负载，而编辑器**必须继续无视它**

`keys.py` 的 `Key` 只有 `name` + `text`，鼠标要带 `button/col/row`。加一个可选字段
`mouse: Optional[MouseEvent]`。

**已核对**：`LineEditor.handle` 是一串 `elif name == …`，**没有 catch-all 插入**，
未知 name 落到最后直接 `return None`。所以 `Key("mouse", …)` 不会被灌进输入框。

> **但这条要补一条测试钉住**：它现在成立是因为「恰好没人写 else」。
> 将来谁顺手加个 `else: self._insert(key.text)`，鼠标字节就会哗哗地打进输入框，
> 而**没有任何测试会红**。T1 补一条 `test_mouse_keys_never_reach_the_editor`。

### ② Transcript 条目要**有状态**，缓存 key 得跟着变

feature 13 的 `TranscriptEntry` 是「一个渲染函数 + 按宽度的单槽缓存」。
点击展开要求条目记住自己是折叠还是展开，于是：

```
缓存 key：  width          →   (width, 展开态)
```

**漏了这一步的症状是「点了没反应」**——渲染函数换了，缓存还发着旧的行。
与 13 那条「缓存 key 必须含宽度」是同一个坑的第二次，T7 的注入反证就打这里。

### ③ 选区高亮插在渲染管线的**哪一层**

必须在 `_compose` 产出 frame、**且 `_fit` 截断之后**、写字节之前套反显——
截断之前套的话列号与最终屏幕对不上（一行被截短，高亮区间还按原长算）。
所以 `AltScreenRenderer` 要能读到选区状态：**与 transcript/scroll 同款注入**，
不在渲染器里存第二份。

## T1 · SGR 1006 解析

**目标**：字节流里的鼠标序列变成可测的事件对象，且**拆包也认得**。

**红**（≥8）
- 按下 `\x1b[<0;12;3M` → `MouseEvent(kind="press", button=0, col=11, row=2)`（**转 0-based**）。
- 松开 `…m` → `kind="release"`；拖动 `\x1b[<32;…M` → `kind="drag"`；
  滚轮 `\x1b[<64;…M` / `<65` → `kind="wheel"`，`delta=-1/+1`。
- **序列被 `os.read` 拆成两半**（`\x1b[<0;12` + `;3M`）仍能拼回一条事件
  ——实测每次 `os.read(4096)` 里有几百条事件，切在中间是必然而非偶然。
- 未知编码（`\x1b[<0;12;3;99M`、1015/1016 形态）**丢弃不崩**。
- 鼠标序列**不得被当成 `unknown` 塞进输入框**。
- `test_mouse_keys_never_reach_the_editor`：把 `Key("mouse", …)` 喂给 `LineEditor.handle`，
  断言 `text` 不变（钉住结构问题①）。
- 注入反证：给 `LineEditor.handle` 加一个 `else: self._insert(...)`，上一条必须变红。

**绿**：`mouse.py` 的 `MouseEvent` + `keys.py` 的一个分支。

## T2 · 事件合并（实测倒逼出来的）

**目标**：一次滚动手势的上百条事件，只产生一帧。

**红**（≥5）
- `merge()` 把一批事件里的 wheel **累加成一个** delta（142 条向上 → 一个 `delta=-142`）。
- 拖动**只留最后一个**（中间过程无意义，焦点只关心「现在在哪」）。
- 按下/松开**不许合并、不许重排**（它们是状态跃迁；顺序错了选区就废了）。
- 混合批次（wheel + press + drag + wheel）合并后的**相对顺序**正确。
- **喂 142 条 wheel（实测数字）只产生 1 帧**——断言渲染器的 `draw` 被调用 1 次。
- 注入反证：去掉累加、逐条 `scroll_by` + `draw`，上一条必须变红
  （**它会红，因为断言的是 draw 次数而不是滚动结果**——滚动结果两种写法是一样的，
  照结果断言就是假绿，feature 15 那三条的同款陷阱）。

**绿**：`mouse.merge(events) -> list[MouseEvent]`，纯函数。

## T3 · 滚轮接线

**目标**：滚轮滚 transcript，跟随语义复用 feature 13 的状态机。

**红**（≥5）
- 向上滚 N 格 → `scroll_top` 减 `N * WHEEL_LINES`；向下同理。
- 向上滚**关闭跟随**；滚到底**恢复跟随**（复用 13 的 `ScrollState`，这里只验接线）。
- 指针落在 dock 上滚，**照样滚 transcript**（pai 只有一个滚动区）。
- `tui.mouse` 关或非 alt 模式下，wheel 事件不该存在（没开上报）——
  但即便收到也**不许崩**（终端可能残留模式）。
- `WHEEL_LINES = 3` 旁必须写「凭手感定，无实测依据」（AGENTS 的照抄常数纪律）。

**绿**：`app._key` 的鼠标分支 + `_SCROLL_KEYS` 之外的一条路。

## T4 · 选区状态机（**锚在逻辑行号**）

**目标**：pai 相对 CC 的简化点——选区跟着内容走，不跟着屏幕走。

**红**（≥8）
- 按下记锚点（transcript 逻辑行 + 列），拖动更新焦点，松开结束但**保留**选区。
- **裸点击不产生选区**：与锚点同格的第一次移动不算数（照 CC；否则单击会清剪贴板、
  还与 T7 的点击展开打架）。
- 归一化：焦点在锚点之前时，start/end 自动交换。
- **滚动之后选区仍框住同样的内容**（本 task 的核心断言，也是「锚在逻辑行」的全部意义）。
- **内容追加之后**（agent 又说了一句）选区不漂。
- 取文本：跨行拼接、逐行 `rstrip`、**剥净转义序列**、中文**按列**切不切半个字。
- 空选区取文本 → 空串（不许返回一个空格）。
- Esc / 下一次按下清除选区。
- 注入反证：把锚点改成屏幕行号，「滚动后选区仍框住同样内容」必须变红。

**绿**：`selection.py`，纯状态机，不碰终端也不碰渲染。

## T5 · 选区高亮

**目标**：屏幕上看得见选中了什么。

**红**（≥6）
- 帧里被选中的区间套上 `\x1b[7m` … `\x1b[27m`。
- **按显示列切片**：中文行选中「第 3-5 列」不许切出半个字（复用 ANSI 感知的列计算）。
- 高亮**在 `_fit` 截断之后**套（构造一个超宽行，断言高亮列号与最终屏幕一致）。
- 选区跨多行：首行从 start 列到行尾、末行从行首到 end 列、中间整行。
- 选区**只出现在 transcript 区域**，dock 那几行不受影响。
- 无选区时帧与今天**逐字节相同**（回归防线）。
- 注入反证：把「截断之后套」改成「截断之前套」，第 3 条必须变红。

**绿**：`altscreen.py` 加一层，选区状态注入。

## T6 · 复制：双路径 + 可见反馈

**目标**：复制真的进剪贴板，进不去要说实话。

**红**（≥7）
- 本地：调系统剪贴板命令（macOS `pbcopy`；Linux 按序 `wl-copy`/`xclip`/`xsel`），
  **看退出码**判成败（子进程注入，不真跑）。
- 命令不存在 / 非零退出 / **超时 0.5s** 三条失败路径各一条测试，且**都不阻塞主循环**。
- `SSH_CONNECTION` 有值 → 直接走 OSC 52。
- 本地全失败 → 兜底 OSC 52。
- **措辞**：系统剪贴板成功 → `已复制 N 行`；只发了 OSC 52 → `已尝试复制（OSC 52）`。
  一条测试**断言 OSC 52 路径的提示语里没有「已复制」**（实测它会静默失败，
  说「已复制」就是骗人）。
- OSC 52 载荷是 base64 且以 `\x1b]52;c;` 开头。
- 注入反证：把 OSC 52 路径的措辞改成「已复制」，上一条必须变红。

**绿**：`clipboard.py`，命令与环境全部可注入。

## T7 · 点击展开/折叠

**目标**：用户最早那句「我想这个 bash 和 bash 的结果能点」。

**红**（≥6）
- `Transcript.slice` 顺带返回**每一行属于哪个条目**——**这就是命中测试的全部**
  （pai 的布局是一维的，不需要 CC 的矩形树）。
- 点击工具条目的任意一行 → 该条目展开；再点 → 收起。
- 展开态渲染完整输出，折叠态渲染一行（沿用现有形态）。
- **换宽度后展开态仍正确**——缓存 key 含展开态（结构问题②）。
- 点在空白行/dock 上：不炸、不改任何状态。
- 点击与选区不打架：**按下后拖过再松开 = 选区，不触发展开**。
- 注入反证：把缓存 key 退回只含宽度，「点了要变」必须变红
  （**症状是「点了没反应」，与 13 那条「换宽度不重算」是同一个坑的第二次**）。

**绿**：`transcript.py` 的条目状态 + `app.py` 的点击路由。

## T8 · 生命周期与开关

**目标**：鼠标模式不许泄漏到 shell 里。

**红**（≥5）
- 进：鼠标使能**跟在 `?1049h` 之后**（同一次写入，断言先后）。
- 出：**关鼠标早于 `?1049l`**（照 CC：关鼠标要给终端往返的时间，
  否则事件在恢复 cooked 模式期间到达，会**回显到屏幕或漏进 shell**）。
- 异常抛出 / `Ctrl+D` / 正常退出三条路径都复原。
- `tui.mouse: false` → 输出里**没有任何 `?100` 鼠标序列**，且回到 13 的行为。
- main-screen 与非 tty：一个鼠标序列都不发。

**绿**：`terminal.py` + `settings.py`。
