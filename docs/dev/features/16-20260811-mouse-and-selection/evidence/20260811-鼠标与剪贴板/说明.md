# 鼠标与剪贴板反向对照（动工前）—— 2026-08-11

feature 13 的手工清单里，鼠标那一整块**一条都没测到**（缺辅助功能授权）。
本 feature 要接管鼠标、还要自己写剪贴板，所以这些不是验收项，**是设计输入**。

## 1. **OSC 52 在 iTerm2 3.6.11 上写不进剪贴板**（决定性）

`探针/osc52_test.command`：在一个新开的 iTerm2 窗口里发两次 OSC 52，
分别用 BEL（`\x07`）与 ST（`\x1b\\`）结尾，内容各不相同；
跑之前先 `pbcopy` 一个哨兵值。

```
跑之前： CLIPBOARD-BEFORE
两次 OSC 52 之后： CLIPBOARD-BEFORE     ← 一个字都没变
```

**两种结尾都失败，且完全静默**——终端不报错，应用也无从知道自己没写成。

成因大概率是 iTerm2 的「Applications in terminal may access clipboard」默认关闭
（未逐项核实设置，只记现象）。这一点**不影响结论**，因为
[K alt-screen-and-mouse 第五节](../../../../../knowledge/tui/alt-screen-and-mouse.md)
已经证明**能力探测这条路是堵的**（DECRQM 不可移植），所以「先问终端支不支持 OSC 52」
做不到。

> **对本 feature 的直接约束**：
> ① **本地必须走 `pbcopy`**，OSC 52 只能当 ssh/tmux 场景的兜底，不能当主路径；
> ② pi 的做法（`tui-alt-screen.ts` 里只发 OSC 52）**在这台机器上是坏的**——
> 参照实现能跑通，不代表在你的终端上能跑通；
> ③ 我在拍板问里把「先只做 OSC 52」标成了推荐，**这个推荐会交付一个静默失效的复制功能**。
> 用户选了「兵分两路」，实测证明用户是对的。

## 2. 合成鼠标事件仍然做不到——而我一度以为可以

辅助功能权限**分两级**，我把它们搞混了：

```
osascript -e 'tell application "System Events" to get name of first process'
  → 正常返回（读进程列表：允许）
osascript -e 'tell application "System Events" to click at {300, 300}'
  → -25211「不允许辅助访问」（合成输入事件：拒绝）
```

我拿第一条当作「权限有了」的判据，写完探针跑起来才在第二条上撞墙。
**这是「观测工具骗人」的第四种形态：能力探测本身探的是另一个能力**
（[K engineering/instruments-lie.md](../../../../../knowledge/engineering/instruments-lie.md)）。

于是真实鼠标字节只能由真人跑，见[手工清单](手工清单.md)。**2026-08-11 用户跑了两次**，
结果见下面第 3-4 条。

## 3. 第一次跑：**一次滚动手势 = 上百条事件**（决定性）

原始日志 `第一次-原始日志.log`。用户用触控板滚动，6 秒内收到 **1846 字节 ≈ 142 条**
wheel 事件（每条 `\x1b[<64;104;22M` 13 字节），另一段 10 秒收到 214 条。

> **对本 feature 的硬约束：滚轮事件必须合并。**
> pai 的一帧是整屏 diff，每条 wheel 都触发重绘 = 两指滑一下就**每秒 20-40 次全屏重绘**。
> 正确做法：一次 poll 把所有 wheel 累加成一个 delta，**只重绘一次**。
> （与 feature 12 撞过的「空闲每 100ms 白刷一帧」同源，量级大得多。）

两条附带事实：
- **滚轮在 `1002` 下就上报了**——滚轮不是 1003 才有的。只要滚轮的话 1002 甚至 1000 就够。
- **坐标恒定不变**（`104;22`）：触控板两指滚动**不移动指针**。wheel 事件里的 x/y 是
  「指针此刻在哪」，用途是命中测试（决定滚哪个区域）；pai 只有一个滚动区，本轮用不上。

### 顺带暴露了探针自己的缺陷（第五种「工具骗人」）

第一版探针**只记原始字节的前 200 字节**，而三段的开头恰好全是滚轮事件——
于是「1002 与 1003 差多少」「点击/拖动长什么样」两个真正要测的问题**一个都没答上**。
**工具保存的是原始前缀，而我需要的是按类型计数。**
v2（`probe_mouse2.py`）改成按事件类型计数，一次就问出来了。

## 4. 第二次跑（v2，按类型计数）

日志 `第二次-按类型计数.log`：

```
1·只开1002·只移动指针     0 字节 / 0 条事件
2·只开1003·只移动指针     0 字节 / 0 条事件
3·开1003·点击与拖动       1856 字节 / 154 条 / 148 个不同坐标
                            拖动(按钮0) 153 条
                            按下(按钮0)   1 条
```

- **拖动 = 每跨一格一条**（153 条 / 148 个不同坐标）。与滚轮不同：拖动的每一条都
  **携带新信息**（选区焦点移到哪），不能合并；**但重绘要合并**——153 条各画一帧就是满屏抽搐。
- **按下 `\x1b[<0;列;行M`、拖动 `\x1b[<32;列;行M`**（button|32），与源码里的编码一致。
- ⚠️ **松开事件没抓到**（154 条里 0 条 `m` 结尾）——多半是 8 秒到时用户还按着。
  松开恰恰是「松手即复制」的触发点，**记为未观测**，见手工清单。
- ⚠️ **1002 与 1003 两段都是 0 条，分不出差别**。两种可能未排除：用户前两段没真移动指针／
  iTerm2 不上报无按键移动。若是后者，则 **1003 相对 1002 是「买了个空」**
  （hover 高亮在本机做不出来）。**记为未定**，见手工清单。
