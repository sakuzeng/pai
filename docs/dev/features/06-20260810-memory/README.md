## 需求

roadmap 阶段 3：**两套互补机制**（官方明确区分，见 K memory/claude-memory.md 第一节）——

1. **人写的分层指令**：`~/.pai/PAI.md`（用户）→ 向上递归的 `PAI.md`（项目）→
   `PAI.local.md`（本地），拼接进上下文，支持 `@path` 导入。
2. **模型自写的自动记忆**：`MEMORY.md` 索引（每会话加载，有上限）+ 主题文件（按需读），
   模型用 `remember` 工具自己决定写什么。

## 候选方案与确认

### 2026-08-10 brainstorm 四问拍板（用户；问答完整存档，规矩 6）

**问 1**：分层指令拼好后注入到哪里？官方把 CLAUDE.md 作为 **system prompt 之后的
user 消息**传，并自陈「因此没有严格遵守的保证」。
- 候选 A·拼进 system 消息：`SYSTEM_PROMPT` 从常量变成「常量 + 分层指令」。三个好处：
  ① **压缩后自动存活**（`compact()` 重建的就是 `[system]+[摘要]+[保留尾部]`）；
  ② system 是稳定前缀，缓存友好（实测命中率 91.6%，50 倍价差）；③ 遵守度更高。
  代价：与官方行为不一致，学不到「为什么 CC 要重注入」那个坑。
- 候选 B·**照官方，进第一条 user 消息**：忠实还原 CC。代价：**必须额外实现「压缩后
  从磁盘重读重注入」**（不做就是长会话静默失效的 bug），且官方自认遵守度不保证；
  收益：把 CC 那个真实机制连同它的代价完整实现一遍。
- 候选 C·两者都实现可配置：代价是两条路径都要测、两倍维护，且「可配置」在没有真实
  使用数据时就是推迟决策。

**选择：B**。连带后果（写进 spec 验收）：压缩后重注入是**必做项**，不是加分项；
且重注入必须**从磁盘重读**而非用缓存的字符串——官方原话就是「从磁盘重新读取」，
这样用户中途改了 PAI.md 也能生效。

**问 2**：指令文件叫什么名字？（pai 仓库自己就有 `AGENTS.md` + `CLAUDE.md`）
- 候选 A·**自己的 `PAI.md` 三层**：`~/.pai/PAI.md` → 向上递归 `PAI.md` → `PAI.local.md`；
  官方的托管策略层不做。**不读 `AGENTS.md`**——那里写的是「给写 pai 的 AI 的规矩」
  （留痕、TDD、档案门禁），pai 自己当 agent 跑时读到会把开发规约当成任务指令。
- 候选 B·直接读通行的 `AGENTS.md`：零配置即可用，但会吃到大量不适用于自己的内容。
- 候选 C·`PAI.md` 为主、`AGENTS.md` 兜底回退：多一层心智负担，且会偷偷吃到不适用内容。
  （注：官方对 AGENTS.md 的做法是让用户写 `@AGENTS.md` 导入，**不直接读**——
  pai 选 A 后同样可以靠 `@` 导入达成同一效果，主动权在用户手里。）

**选择：A**。

**问 3**：「会话学得的东西写回」由谁触发？
- 候选 A·**做成工具 `remember`，模型自己决定写**：走现有 `@tool`，零额外请求、
  与工具系统同构、离线可测（假 client 脚本里让它调即可）。代价：写什么取决于模型判断。
- 候选 B·会话结束时额外跑一次总结请求：确定会发生，但每会话多花一次钱，
  且 REPL 里「会话结束」定义模糊（Ctrl+D？崩溃？）。
- 候选 C·阶段 3 只做读不做写：roadmap 目标句的后半截直接不做了。

**选择：A**。

**问 4**：写回记忆要不要拦住用户确认？
- 候选 A·**自动写 + 事件提示 + 审计落盘**：官方行为（默认开、模型自决、界面显示
  「Writing memory」），pai 多加一层——写入同时发 `MemoryWritten` 事件并落进会话 JSONL，
  事后可审计；记忆文件本就是纯 markdown，随时可改可删。
- 候选 B·每次写回前用 AskUserQuestion 问真人：打断感强，且 once 模式无真人可问——
  写回会退化成 REPL 独有能力。
- 候选 C·只在 `/remember` 显式命令时写：退化成手写笔记，官方那句「从你的更正中学习、
  无需手动操作」就没实现。

**选择：A**。

## 结果与测试

7 个 task 严格 TDD，每步真实数字见 [devlog.md](devlog.md)：

| task | 内容 | 提交后全套 |
|---|---|---|
| 1 | 分层发现（用户级 → 根 → cwd，local 在后） | 199 passed |
| 2 | `@path` 导入（相对基准 / 4 跳 / 环 / 代码块内不算） | 206 passed |
| 3 | 自动记忆读取（git 根定 key，200 行 + 25KB 双上限） | 213 passed |
| 4 | 接线进 loop（第一条 user 消息）与 once/REPL | 220 passed |
| 5 | **压缩后从磁盘重读重注入**（唯一「不做就是 bug」的一环） | 223 passed |
| 6 | `remember` 工具 + 路径穿越防御 + `MemoryWritten` | 231 passed |
| 7 | `/memory` 命令 | **235 passed, 3 deselected** |

**两处红出来的真问题**：
1. Task 2 的红是**测试自己的 off-by-one**——官方「最大 4 跳」从根文档起算，
   改的是测试不是实现，并把算法写进测试 docstring。
2. Task 6 初版测试用 `remember(..., directory=Path)` 传目录，**`@tool` 只认标量参数，
   `Path` 在装饰期就报错**；而把目录做成 `str` 参数等于让模型自己挑写盘位置——
   比路径穿越还糟。改用注入点（D#40 同款）。

**与计划的一处偏离**：plan 要求 `MemoryWritten` 事件落进会话 JSONL 审计；实现时发现
**审计已经免费有了**（`remember` 的调用与结果本就以 `assistant.tool_calls` + `tool` 消息落盘），
所以没重复落一份，该事件只负责可见性。

**端到端冒烟**（真跑，非测试）：`AGENTS.md` 确实没被读、`@detail.md` 展开、`local` 在后、
`remember` 写文件并建索引、`../../etc/passwd` 被拒且一个文件都没写出来、
写回内容出现在下一次 `build_context()` 里。
