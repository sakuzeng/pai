四条，逐条的验收标准：

1. 默认 token 预算撑不过一个中等任务（45-C3）。默认 20 万，实测 11 步真实任务烧到 131820；
   用户 2026-09-10 那次 217839 撞顶，且当时不知道「再敲一句就会接着做」——REPL 里 `spent_tokens`
   是 `run_agent` 的局部变量，下一轮本来就重新计数，这个事实从来没人说过。
   验收：默认值提到 50 万；撞顶那句话说清三件事——停在第几步、再说一句就接着做、
   要放宽用 `--max-tokens`；`--help` 同步；once 模式（没有下一轮）不说「再说一句」那半句。

2. 计时器把等人回答的时间算进「用时」（45-C2）。真跑显示 `⠹ 3m59s`，其中 3m55s 是弹窗在等人。
   验收：权限弹窗与 `ask_user_question` 期间计时暂停，答完接着走；活动区、状态行、轮末摘要
   三处的用时都不含等人时长；注入时钟离线可测。

3. 长工作目录把 footer 撑满（45-B3）。`_justify` 装不下时先牺牲右边，于是模型与上下文占比整条消失。
   验收：给一个很长的 cwd，footer 里模型与上下文占比仍在；路径中间省略、保留最后一段
   （用户最需要知道的是「我在哪个项目」）；右边也装不下时才退回原来的牺牲顺序。

4. 权限弹窗文案是内部术语（45-C1）。现在第二行是「`bash` 不参与工作目录边界判定（未声明路径语义），
   按最保守处理」——对用户讲 D#52 的实现细节。
   验收：四类 ask 的文案各说清三件事（为什么问、允许之后会怎样、怎么配才不再问）：
   不参与边界的工具（bash / MCP）、界外读、写文件、危险写；`/permissions` 的展示同步；
   `Decision.reason` 是唯一出处（弹窗与事件流同一份文本）。
   诚实边界（45 复盘质疑一）：45 那次我自动应答了每个弹窗、没读过文案，严重程度判不了，
   所以按「说清三件事」验收，不按「用户觉得好」。

## 候选方案与确认

四问的候选与取舍在 [features/52 的立项版本](../52-20260913-word-wrap/README.md) 里已写过一轮

问 1：默认 token 预算怎么改？
- 候选 A·提到 50 万 + 撞顶提示给出路。50 万在 v4-flash 上最坏约 1 元。
- 候选 B·维持 20 万只改提示。用户还会在同样的地方撞到。
- 候选 C·去掉默认预算。平台侧没有消费限额，这是唯一的自动防线，不能去。
选择：A。

问 2：权限文案改在哪一层？
- 候选 A·直接改 `permissions.py` 的 `Decision.reason` 原文。一处改、弹窗与事件流同时变人话。
- 候选 B·`gate` 层加「术语 → 人话」映射表，只改显示。同一件事两份文案，迟早漂。
选择：A（AGENTS「唯一出处」）。代价是 `reason` 也进观测流与测试断言，要一起改。

问 3：计时暂停做在哪？
- 候选 A·`Dock` 自己记「等人时长」：问真人前 `pause()`、答完 `resume()`，`elapsed` 扣掉累计等待。
- 候选 B·做成事件（`AskStarted` / `AskEnded`）让 dock 监听。events 的准入判据是
  「上下文被改写没有」，这条不符合，会把事件流变成杂物间。
选择：A。

问 4：footer 装不下时怎么取舍？
- 候选 A·路径中间省略（`~/a/…/pai`）保住右边，保留最后一段。
- 候选 B·维持现状（先牺牲右边）。用户截图里模型与上下文占比就是这么消失的。
选择：A。

## 结果与总结

交付（2026-09-13）：45 真用清单的最后四条全部做掉。

- 预算：默认 50 万；撞顶说清「停在第几步 / 再说一句就接着做 / 要放宽用 `--max-tokens`」，
  once 不说中间那半句（`run_agent` 为此加 `interactive` 参数）。
- 计时：`Dock.pause_clock/resume_clock` + `_elapsed()`，TUI 的 `ask_human` try/finally 包住对话框。
- footer：先压路径（中间省略保住最后一段）再牺牲右边，长 cwd 下模型与上下文占比不再消失。
- 权限文案：四类 ask 的 `reason` 各说清三件事，`/permissions` 同步；`reason` 是唯一出处。
- 测试：`tests/test_four_frictions.py` 15 条；五条既有测试的判据从「术语在不在」改成
  「说没说清那件事」（其中一条本来已因文案变化退化成空断言）。两处注入反证各红。
- 数字：相关 `15 passed`，全量 `1914 passed`（更新 STATUS 前一跑 `1 failed, 1913 passed,
  8 deselected in 201.04s`，红的是测试数校验）。

发现一条：「再说一句就接着做」一直成立（`spent_tokens` 是 `run_agent` 的局部变量，REPL 下一轮
重新计数）却从没说过——用户 2026-09-10 撞顶时以为活儿断了。改默认值只是缓解，说出来才是修复。
