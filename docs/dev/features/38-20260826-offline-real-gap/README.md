## 需求

用户 2026-08-26 指示：「当前代码层面和真实使用的差距，我想改善这个」。

背景：roadmap 阶段 1-7 全部有交付、1487 条测试全绿，但有一批链路从来没有在
真实条件下跑过。开工前把「差距」分成三类，用户拍板三类都覆盖：

1. 离线其实能验、只是一直没验：自动压缩全链、流中途中断
   （feature 15 遗留登记了十五天的两条）。
2. 只有真模型能验：`remember` → 召回的完整链路（实测发现它在真实会话里
   一次都没被调用过）、路径作用域规则模型到底听不听。
3. 只有真人 + 真终端能验：中文 IME 候选框位置、resize 视觉残留、颜色。

动工前的第一个发现，也是本轮的引子：假 provider 对每一轮都回固定的
`usage`（`prompt_tokens: 100, total_tokens: 120`），而真 provider 的
`prompt_tokens` 随对话增长。后果不是「不够真」这么软——相邻锚点的真实差值恒为 0，
于是 `find_cut_point` 结构上永远返回「无可压」，压缩链路在 e2e 里走不到。
测量仪器自己把那条路堵死了，而这正是 2026-08-10 用户实测暴露、至今还开着的
那条「压缩链路在真实使用中一次都没被走到过」。

验收标准：

1. 假 provider 的 usage 与真 provider 同形（随对话增长），既有 e2e 不因此假绿。
2. 一条 e2e 证明自动压缩在真进程 + 真 pty 里真的发生过（屏幕上看得见，
   且假 provider 真的收到过一次不带 tools 的摘要请求）。
3. 一条 e2e 证明流中途 Ctrl+C 掐得断且 REPL 不死（掐完还能再问一句）。
4. 只有真模型能验的两条写成 `--llm` 冒烟：默认跳过（写不花钱，跑才花钱）。
5. 只有真人真终端能验的如实做成手工清单，不假装自动化了。
6. `./test.sh` 全绿，STATUS 数字同步。

## 候选方案与确认

问 1：本轮覆盖到哪一类差距？

- 候选 A·三类都覆盖：①离线能兑现的（假 provider usage 修真 + 压缩 e2e +
  中断 e2e）②真模型那类写成 `--llm` 冒烟（默认跳过）③真人真终端那类做成手工清单。
  外加 dogfooding 地基。工作量最大，但三类各有各的兑现方式，不互相挡。
- 候选 B·只做①：当天可交付、不花钱，直接兑现 2026-08-10 那条旧账；
  真模型那一类的缺口原样留着。
- 候选 C·只做②+③：把「现在验不了的」变成「一条命令就能验」，
  代价是压缩那条旧账继续挂着，而它现在就能关掉。

选择：A（三类都覆盖）。理由：用户选了推荐项。

### 动工后的一处修正（如实记）

拍板时把「把仓库自己的 `AGENTS.md` 按路径拆进 `.pai/rules/`」算进了 A 的
dogfooding 地基，动手前发现这条不能照做：`AGENTS.md` 是 Claude Code 的唯一
加载入口（`CLAUDE.md` 里一句 `@AGENTS.md`），而 pai 的规则是「碰到匹配文件才
加载」——把内容搬出去，pai 那边省了常驻，Claude Code 那边就看不见了。
两个消费者的加载机制不同，同一份内容不能同时满足。

改做法：不动 `AGENTS.md`，另写一条真正只在特定路径下才相关的新规则当示范
（`.pai/rules/tests.md`：写测试时才需要记住的几条，含本仓库特有的坑）。
「把 AGENTS.md 拆薄」这件事单独登记 TODO——它要先解决 Claude Code 那半边。

## 结果与总结

三类差距各自兑现，测试从 1487 → 1492（`1492 passed, 5 deselected`）。

第一类（离线其实能验、只是一直没验）——两条 e2e，都是 feature 15 登记了
十五天的账，而且此前结构上跑不到：

1. 假 provider 的 `usage` 改成随对话增长（并可按轮钉死）。这不是「更像」，
   是解锁：`prompt_tokens` 恒定 → 相邻锚差值恒为 0 → 切点永远「无可压」。
2. 自动压缩在真进程 + 真 pty 里真的发生了，屏幕上看得见、摘要请求真的发出去了。
   顺带把 STATUS 已知缺陷 1 的「两步节奏」（先一次锚点不足、再压）
   从设计推论变成跑出来的事实。
3. 流中途 Ctrl+C：掐得断（整段答案不许完整出现）且 REPL 不死（掐完还能再问一句）。

第二类（只有真模型能验）——写成 `--llm` 冒烟，默认跳过：`remember` → 召回全链
（缺口：真实会话里 `remember` 一次都没被调用过）、路径作用域规则模型到底听不听
（feature 36 交付时登记的那条）。写不花钱、跑才花钱；离线把管线（参数名/签名）
验过一遍，行为断言仍只有真跑才验得到，如实声明。

第三类（只有真人真终端能验）——`evidence/手工清单.md` 六节，
末尾写明「本清单尚未被人跑过」。

外加：仓库自己成了 feature 36 的第一个用户（`.pai/rules/tests.md`）；
知识回流一条——`instruments-lie.md` 从四种骗法扩到五种。
