「真实项目任务用哪种代码场景？建议先做 6 题（查实现、修 bug、补测试各 2 题），按历史问题分成开发集 3 题与保留集 3 题；同一问题的变体不跨集合。」

- 「B：从 pai 历史裁剪真实模块——环境更轻、判分更容易；需要明确它只代表模块任务，不能当完整项目能力。」

用户选择原文：「A：pai 完整历史仓库快照（推荐）——更接近真实开发；冻结起始提交，移除答案与交付文档，准备和判分成本较高。」。用户未另外陈述理由。

### 问 3

问题原文：

「每题怎样做离线判分？查实现核对目标符号；修 bug 与补测试需要选回归范围。两种都要求参考解能通过，并拒绝空测试、跳过测试、修改受保护文件等假通过。」

- 「A：相关回归 + 独立外部判据（推荐）——每题冻结相关测试；补测试任务还要检测预置错误实现。成本可控，但不宣称整个历史版本全量回归通过。」
- 「B：相关判据 + 历史全量离线回归——覆盖更广，但旧文档数字检查、终端测试与环境差异也要单独处理，耗时和维护成本更高。」

用户选择原文：「A：相关回归 + 独立外部判据（推荐）——每题冻结相关测试；补测试任务还要检测预置错误实现。成本可控，但不宣称整个历史版本全量回归通过。」。用户未另外陈述理由。

### 问 4

问题原文：

「保留集怎样开放？它用于后续改提示词和工具时避免边看结果边调题，本轮只验证评分器与参考解。」

- 「A：默认只跑开发集，保留集须显式选择（推荐）——分别输出结果、记录案例与判分哈希；保留集评分设施照样离线验证。」
- 「B：默认两组都跑、报告分开——操作简单，但后续开发容易反复看到保留集成绩，隔离作用更弱。」

用户选择原文：「A：默认只跑开发集，保留集须显式选择（推荐）——分别输出结果、记录案例与判分哈希；保留集评分设施照样离线验证。」。用户未另外陈述理由。
