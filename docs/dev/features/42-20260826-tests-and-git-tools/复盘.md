# 42-tests-and-git-tools · 复盘

## 学到了什么

上一轮复盘我写下的那条「把顺手这件事换一个有名字、能被判定的入口去做」，
这一轮直接又用了一次，而且这次看清了它真正的机制：**限制入参，换取自动放行**。
`search_files` 能自动放行是因为它只能表达「一个搜索根」；`run_tests` 能，
是因为它只能表达「跑哪一部分」而不能表达「跑什么」；`git_read` 能，
是因为 argv 由 pai 拼、模型连一条完整命令都构造不出来。三次是同一个交易：
工具越是表达不了坏事，权限层越不需要在运行期去判它。
反过来，bash 之所以永远只能 ask，正是因为它的入参能表达一切。
这条交易以后可以直接当设计工具用：想让一个动作不被问，先问「怎么把它的入参
收窄到坏事说不出口」，而不是「怎么给它开一条放行规则」。

第二条，关于「不说谎的字段」值多少钱。`EXEC` 这一档在行为上一分钱没买到——
它和 READ 的兜底待遇一模一样。买到的全部是判据：下一个执行类工具来的时候，
「它算哪一档」是答得上的。而候选 B（写成 READ）省下的那点改动，
代价是把一个会静默出错的谎留在类型系统里。这类取舍平时很难说服人，
因为收益要等到「下一次」才兑现；这次能拍下来，是因为把「谎不会让任何测试变红」
这句话摆到了台面上。

## 哪里走了弯路，为什么

两次都栽在同一类东西上：**验收仪器自己有问题**，而现象与「被测的东西坏了」
一模一样。

第一次是注入反证的 shell 函数。我写了 `T="a b"` 然后 `pytest $T`，
zsh 不做无引号变量的词分割，于是九次注入全部「no tests ran」。
输出里那行 `no tests ran in 0.00s` 我扫过去差点读成「反证不红」——
如果当时手快一点，会得出「这九处都没被测试覆盖」这个完全错误的结论，
然后去补九条根本不需要的测试。救了我的是「0.00s」这个数字不合理，
而不是我认真读了输出。

第二次是 `acceptEdits` 那条注入不红。这次我按 mutation-testing-pitfalls
第五条先查了实现，实现是对的——问题在测试挑错了可观察点：界外有 `dirs.contains`
挡着、界内兜底本来就 allow，两种场景都分不出第 5 步有没有放宽。
只有 `default_decision="deny"` 时才分得出。这一步花的时间不算弯路，
它本来就是那条规矩要买的东西；值得记的是**「找不到可观察点」本身是个信号**：
如果一个改动在所有能想到的场景下都观察不到，那要么它确实无害，
要么你还没想到那个场景，而这两者必须分清楚再往下走。

## 我现在质疑什么

一、我给这两个工具的自动放行写下了一个存续条件——「跑什么不由模型决定」——
然后把它放进了模块注释和 D#77。这正是我在 feature 40 复盘里批评过的那种东西：
一条写下来但没有人来查的判据。它比一般的 TODO 更危险，因为它不是「还没做的事」，
是「已经在依赖的假设」。今天没人会去给 `run_tests` 加一个 `command` 参数，
但半年后有人嫌探测表不够用时会想这么干，而那一刻不会有任何东西变红。
我登记了 TODO 说要写一条机器检查，但也如实写了「判据怎么写还没想清楚」——
所以现在的状态是：我知道这里有个洞，我承认我没堵。

二、`git_read` 的 flag 白名单我写得挺得意（失效方向朝安全那侧），
但我没有验证过它在真实使用中够不够用。我列的那些 flag 是我凭印象觉得常用的，
一次都没有让模型真的用它干活过。很可能第一次真用就会撞上三个被拒的合法 flag，
而那时的体验是「这个工具老是拒绝我」——比走 bash 被问一次还烦。
「白名单漏写只是被拒一次，模型一句话就能改」这个说法成立的前提是漏得不多，
而我对「漏得多不多」一个数据都没有。

三、这一轮我第三次写了形状一模一样的「默认根解析 + matcher 包装」
（`search_root` / `test_root` / `repo_root`）。我在 TODO 里登记了「第三份出现
意味着该抽了」，还特意按 40 复盘学的写了触发条件。但诚实地说：三份都是我自己
在两天内写的，我在写第三份的时候就知道它是第三份，却还是先写完再登记。
「等触发条件到了再抽」在这里更像一句免责声明——真正的原因是我不想在交付路径上
再插一个重构。

## 下次怎么做更好

自己临时写的验收脚本，先用一个**已知会失败的输入**验一次它自己。
这一轮的 shell 函数如果我第一次跑之前先不注入、直接跑一遍看到 `34 passed`，
就不会有后面那九次空转（我实际上是在第二轮才加了「=== 基线 ===」那一步，
而它当场就暴露了问题）。这条比「注意 zsh 不分词」有用得多——
具体的坑记不住，但「仪器先自检」是个能一直执行的动作。
