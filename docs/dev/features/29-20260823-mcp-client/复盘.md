# 29 · 复盘（四问）

## 学到什么

- 反向对照的探针可以直接变成交付物的一部分：动工前手写的 70 行探针 server
  验证了「手写协议可行」，转身就成了 tests/fake_mcp_server.py 的骨架——
  证据面（记日志）与功能面（回应答）分开设计的探针天然就是好夹具。
- 「三家对照」在 MCP 上第一次出现参照缺位形态：pi 显式不做。缺位本身是
  高价值参照——它把「不做什么、为什么」的论证做完了（225 vs 13,000 token），
  pai 的裁剪判据直接受益。以后遇到参照缺位不要跳过，去挖它不做的理由。
- 权限层的「结构性免费」第三次兑现：skills 时 preflight 流水线让 skill 工具
  免费获得治理，27 时兜底给了豁免位挂点，这次「未声明路径语义→ask」的兜底
  恰好就是 CC 的 MCP 默认档位、fnmatch 规则恰好就是 server 级通配——
  feature 07/09 打的地基让 MCP 权限一行引擎代码都不用改。dsh 为同一件事
  留下的是「前缀买了空头期权」的缺口。

## 哪里走了弯路

- T2 的 hash 语义先抄了 dsh（归一化有改动即 hash）再对照 spec 才发现拍的是
  「hash 只兜超长」——写实现时开着参照笔记容易「顺手抄全」，spec 才是拍过板
  的边界。红测试抓住了它，但这红本可以不发生。
- 撞名测试的夹具两个名归一化后差一个下划线根本不撞——写「撞名」测试前先
  手算一遍归一化结果，两分钟省一轮红。
- e2e 一次 NameError 假红（测试内漏 import）。

## 我现在质疑什么

- 质疑 interactive 的 atexit 关闭：取舍是「多出口函数不做大缩进」，但 atexit
  在测试进程里累积注册（每次 run_interactive 一条），且 REPL 结束到进程退出
  之间 server 子进程多活一小段。close 幂等让这无害，但「无害的不确定性」
  正是 25 复核那类检查员会盯的地方。若将来 run_interactive 重构出单一出口，
  应顺手改成确定性关闭。
- 质疑「v1 不告知模型连接失败」：反向对照 P3 证明 CC 文档的该行为实测未复现，
  所以 pai 没抄——但后果是模型完全不知道有个 server 没起来，可能反复尝试
  一个不存在的工具名。遗留里记了，真实使用回来的第一批反馈大概率是它。
- 质疑输出预算的字符换算：100k 字符 ≈ 25k token 的 4 倍换算对中文偏大
  （中文约 1.5-2 字符/token，100k 字符可能是 50k+ token）——对中文重的
  server 结果，预算实际比 CC 宽一倍。校准时（25 遗留 3 同批）该按字节或
  真实 token 计。
- 质疑 dirty-stdout 容忍的边界：非 JSON 行静默丢弃 + 计数都没有，server
  的 stdout 污染完全不可见。pi 有 output-guard 思路（防的是反方向），
  pai 至少该在丢弃行数超阈值时 warn 一次。

## 下次怎么做更好

- 实现时把 spec 开在旁边而不是参照笔记——笔记是「他们怎么做」，spec 是
  「我们拍了什么」，抄串了红测试兜底但浪费一轮。
- 「绿于到达」的测试在写下时就标注（这次 T4 有三条、T5 一条，devlog 都记了）
  ——25 复盘立的规矩执行到位，继续保持。
