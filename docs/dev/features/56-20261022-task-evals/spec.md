# 56-task-evals · spec

本文依据用户逐项选择定稿：固定小仓库、acceptEdits、正常结束且产物正确，范围和预算沿用已确认问答。见 [完整问答](README.md#确认)。

## 背景与问题

feature 32 能回放一条真实轨迹、验证简单文件创建；feature 47 测单步工具选择。
二者都不能回答「pai 能否完成一整件开发任务、复跑是否稳定、花了多少代价」。
本次沿用 evals 入口和工件体系，补最小任务集、外部判分、串行复跑与汇总。

## 目标（做什么）

1. 冻结三个小型 Python 仓库夹具及中文任务，分别覆盖查实现、修小 bug、补测试。
2. 每次建立新的工作目录与 HOME，用实际 `modes.once.run_once` 装配完整 pai 链路；父进程负责期限和判分。
3. 固定案例、prompt、模型和权限设置，各跑三次，保留成功及失败的全部轨迹与产物。
4. 用外部判据计算成功率并汇总耗时、token、工具调用、权限拒绝；明确缺失数据和未完成试验。

## 非目标（明确不做什么）

本轮不改工具引导、system prompt、模型默认值或 loop 行为；不做 A/B 排名、模型 judge、并行、交互权限弹窗或压缩参数校准。
不把三类小夹具的结果外推成真实项目成功率，也不声明性能提升或确定性。
用户本地 `.env` 已选择 `deepseek-flash`，此改动不入库；评测显式冻结该配置名，不依赖夹具目录寻找 dotenv。

## 设计要点

### 入口与模块边界

沿用 `./eval.sh` 的默认离线路径。增加显式任务评测入口 `./eval.sh --tasks`（离线验证）和
`./eval.sh --tasks --llm`（真实任务集，需要 key 与既有付费开关）；具体参数解析在 plan 定稿时落实。
原 `./eval.sh` 与 `./eval.sh --llm` 的既有语义保持，新增任务集避免被旧入口意外执行。

可离线测试的案例契约、指标和汇总逻辑置于 `src/pai/evals/`；任务夹具、评分程序与 pytest 套件置于 `evals/`。
子进程 worker 调公开的 `run_once` 与事件回调，不 import loop 私有实现，不复制另一套 agent loop。
测试收集边界保持 `tests/` 与 `evals/` 分开。

### 三个任务与预先固定的判分

| 任务 | 模型要完成什么 | 评分依据 |
|---|---|---|
| 查实现 | 在含干扰模块的夹具里定位指定行为，写 `answer.json` | JSON 的路径和函数名匹配事先固定的目标；其余受保护文件不变 |
| 修小 bug | 修复夹具中一个明确、可复现的边界 bug，可运行可见测试 | 预检证明原实现不满足外部测试；修改后普通与边界测试通过，且只改允许的生产文件 |
| 补测试 | 为既有正确实现增加 pytest 测试 | 生产代码不变；新增测试在正确版本通过，且对预置的每个错误实现都因行为断言而失败 |

三个任务的实际代码、目标行为、允许改动集合、外部测试与错误实现先签入并通过离线契约检查，再开始真跑。
任务 prompt 说明目标和允许范围，不泄漏隐藏用例或错误实现。判分程序位于模型工作目录之外，评分副本独立运行。
新增测试的语法/导入错误、超时和 pytest 收集失败不算有效地识别错误实现；必须收集到测试并出现断言失败。
修 bug 的删除测试、补测试的修改生产代码、查实现的额外改动都不能通过评分。
自述「完成」或进程退出码 0 不作为任务成功依据。

### 隔离、权限与产物

每次运行使用新建的工作目录、HOME、临时目录和最小 Git 仓库，不复制用户的设置、记忆、skills、MCP、hooks 或历史。
环境按白名单构建：解释器/必要系统运行变量与明确的 provider endpoint、key、model；清除其他 PAI 配置覆盖。
key 只用于 worker 调用 API，不写入 manifest、stdout 摘要或归档；评分子进程不接收 key。

已选权限 A 采用 `acceptEdits`：目录内普通写改与专用读/搜/测试工具按现有语义工作。
不额外放行任意 bash；ask 因无人可问而拒绝，继续回填模型。测试命令由夹具固定，模型使用 `run_tests`。
策略及允许改动清单纳入 manifest；试验之间不继承权限决定。
这是配置与目录隔离，不是系统级沙箱；运行夹具测试仍会执行代码。沿用现有权限边界，不把弹窗不适用计成 0 次。

开发真跑入口与持久工件放 `pai_playground/`。worker 的临时 cwd 位于仓库外的独立临时目录，避免 pai 指令发现器向上继承本仓库 AGENTS；结束后完整工作区快照与原始轨迹保存在该运行目录，完成后将判分结果、汇总、冻结元数据及必要原始轨迹
复制到本档案 `evidence/<日期-主题>/`。作为测试输入的真实轨迹必须签入版本库，并按规范剥除 SessionLog 的 `ts`。
离线执行产生的临时工件沿用 evals 的工件路径，测试只写 tmp_path。
每次留下 prompt、夹具和评分器哈希、Git HEAD 与 dirty 状态、Python 版本、配置模型名、权限、预算、起止时间、stdout/stderr、会话与事件、最终文件/改动快照。
不假装知道 provider 实际后端修订号；未由响应可靠取得的字段写 unknown。

### 生命周期、预算与失败分类

本轮固定三任务各三次，共 9 次，串行；顺序在 manifest 中固定，失败不自动重试。
配置模型为 `deepseek-flash`；每次最多 20 步、20 万 token 软阈值、180 秒，总批次最多 20 分钟。
token 阈值沿用 pai 请求前检查，可能超出最后一次请求；不承诺费用硬上限。
父进程用单调时钟，在启动 worker 前检查总剩余时间，worker 截止时间取单次与批次剩余的较小值。
超时终止进程组，完成回收并记录；评分器也有独立的有限期限，不能无限拖住批次。

结果记录分开表达：

- 执行结果：正常完成、timeout、provider/protocol error、harness error、未启动（总预算耗尽）。
- agent 结束原因：`final` / `budget` / `max_steps` / `interrupted`，缺事件时明确 unknown。
- 评分：pass / fail / unavailable，附每条外部判据及实际输出。

已选口径 A：只有执行正常、agent 正常 final 收尾、外部判据全部通过，才计作完整任务成功；另列产物通过率。
产物已正确但撞预算等未正常收尾的情况单独可查，不悄悄计成功。
provider 或设施异常不混称模型能力失败；汇总保留计划数、启动数、完成数、各类异常数。
总成功率以计划 9 次为分母呈现交付完成情况，同时展示有效完成试验内的评分，避免省略失败或未启动项造成好看数字。

### 指标口径

| 指标 | 来源与缺失处理 |
|---|---|
| 耗时 | 父进程单调时钟；分别记录 agent 时间、评分时间、总时间 |
| token | 累计 session usage 中已报告的 prompt/completion/total；reasoning/cache 字段有则记录，无则 null；缺 usage 不填 0 |
| 工具尝试 | assistant tool_calls 逐调用计数，与权限事件关联；未知工具/参数错误也保留 |
| 开始执行的工具 | `ToolStart` 计数；和尝试分列，不能把被拒绝调用当成执行 |
| 权限拒绝 | 最终 `PermissionDecided.kind == deny` 的调用数 |
| 真人弹窗 | null，原因是 once 无真人提问入口，不适用 |
| 结束原因 | `AgentEnd`，不依据进程退出码推测 |

用例至少验证：中文真实轨迹、并行多 tool_calls、被拒绝调用没有 ToolStart、usage 缺失与畸形记录、budget/steps/timeout、外部判分反证。
工具内部返回字符串错误没有统一错误位，本轮不计算看似精确的「工具错误率」。
主请求用量与 provider 全部计费用量不能强行等同：若出现压缩/召回等未完整入账的侧请求，标记用量覆盖不完整，不据此算总费用。
每类输出成功次数/计划次数、逐次数据、耗时与 token 的可用样本数和中位数/范围；不做显著性检验。

## 验收标准

1. spec 经用户拍板后才修改 src/tests；详细 plan 固定每步先红后绿及目标文件。
2. 三个案例的初始状态、参考解和有效/无效产物经离线验证；评分器能拒绝空测试、删测试、修改生产代码等假通过。
3. 指标测试至少采用一份已提交真实会话轨迹；进程集成经 fake provider 覆盖成功、权限拒绝与异常/期限路径。
4. 默认测试与默认 eval 不调用真实 API；真实任务集仍需显式付费入口与 key，缺门槛给出明确提示。
5. 在已批准预算内执行最多 9 次真实试验，保存每次结果，包括超时、错误、未启动项；不为凑齐成功率扩大预算或自动补跑。
6. 交付包含可复查的数据与汇总，区分离线设施正确性和真实模型表现；./test.sh 相关全量回归完成后写复盘。
7. README、TODO、STATUS、roadmap、全局里程碑与本档案日志按实际结果更新；未完成真实反向对照不能提前勾选。
