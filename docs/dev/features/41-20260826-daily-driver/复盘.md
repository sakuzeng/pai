# 41-daily-driver · 复盘

## 学到了什么

「不被问」这件事有两种做法，而它们看起来一样、代价完全不同。
一种是让用户配一条 allow 规则把询问关掉，一种是让工具具备被判定的资格。
前者是在权限层里挖洞换顺手，后者是把活挪到边界管得着的地方——用户在拍板前
就说了「安全与顺手在这里是真冲突，不要假装能两全」，而做完之后我才看清：
本轮并没有解决那个冲突，只是换了个位置，让冲突落在「自己实现搜索」这个成本上，
而不是落在「边界形同虚设」这个风险上。冲突还在，只是被搬到了付得起的那一侧。
这个搬法可以复用：下次再遇到「安全挡住了顺手」，先问一句「顺手这件事能不能
换一个有名字、能被判定的入口去做」，而不是先去想怎么放宽规则。

第二条，关于「表示层改动」的验收判据。用户点名说「只该影响表示层的改动，
验收标准是解析后的值逐字相等，不是测试还绿」。写 offset 的时候我才体会到这句话的
分量：截断切在行中间与切在行边界，所有既有测试都是绿的，两种做法在
「测试还绿」这个判据下毫无区别；只有「分段读拼回全文逐字相等」这条断言
能把它们分开。判据的强度决定了能发现什么，而弱判据的绿是最像真的假象。

## 哪里走了弯路，为什么

补 decisions 索引那一下是纯粹的自作主张。我看到索引表停在 69、正文有到 75，
以为是漏了，顺手补了 7 行——结果那条本来绿着的一致性测试当场变红。
查下来才明白：校验正文的正则是 `^(\d+)\. `，而 70 起的条目用的是 `## NN.` 标题，
测试根本看不见它们，索引与「它能看见的正文」本来是一致的。也就是说这处漂移
不是漏，是两种形式并存，而机器只认一种。撤回补录、登记 TODO 是对的处理，
但我不该在没看那条测试怎么判之前就动手——顺手改一处「明显的遗漏」，
代价是把一个绿的东西弄红，再花时间弄回去。

第二处是我自己写的测试有 bug：`_tree(tmp_path / "inside")` 里那个目录我没建，
第一次跑起来 `FileNotFoundError`。现象与「实现写错了」在输出里长得不一样，
所以这次没被骗到；但它与 feature 40 复盘里那条「验收工具自己有 bug」是同一族，
第二次出现了。

## 我现在质疑什么

一、`search_files` 的两种模式塞在一个工具里，我现在不确定这是对的。
用「pattern 传空串」切到只按文件名找，代价是 schema 表达不出这两个参数互斥，
模型只能靠 docstring 那一句话；CC 分成 `Grep` 与 `Glob` 两个工具，多半不是随意的。
当时的理由是「用户划的范围是一个搜索工具」，但那句话说的是范围不是形状——
拆成两个仍然是「搜索这一件事」，而我拿范围当了形状的理由。这条已登记 TODO，
触发条件写成「真观察到模型混用两种模式时」，可我知道那个观察不会自己发生。

二、遍历时跳过越界软链这件事，我把它写成了工具自己的自觉。拍板问 3 里我把这条
诚实边界说清楚了，用户也认了，所以过程没问题；但结果是权限层的「一个入参 =
一个路径」这个模型，第一次遇到了「一个入参 = 一片文件」的工具，而我的解法是
让工具自己补上差额。第二个这样的工具出现时，会有第二份 `_escapes_root`。
按 feature 40 复盘学到的那条，我现在就该写清它会在哪个动作里被检查到：
下一次给任何工具挂 `path_access_for` 时，先问「这个入参代表的是一个路径还是一片」。

三、我给 `MAX_FILES_SCANNED = 20000` 写了「未实测的经验值」的注释，也登记了 TODO，
自认为诚实。但诚实地记下一个拍脑袋的数，与不拍这个脑袋，是两件事。
这个数决定的是「多大的仓库开始搜不全」，而搜不全的表现是**结果里少了东西**——
最难被发现的那类错。注释与 TODO 都不会让谁去测它。真正该做的可能是让它先小一点，
小到会被撞上、会有人来抱怨，而不是大到永远撞不上、于是永远不知道对不对。

## 下次怎么做更好

动手改一处「明显的遗漏」之前，先读那条守着它的测试是怎么判的。
本轮 decisions 索引那一下，只要先看一眼 `test_decisions_index_matches_entries`
的两个正则，就能立刻明白 70+ 用的是另一种形式、补录反而会把它弄红——
五秒钟的事，省掉的是一次红、一次撤回、一次重跑。
这条比「顺手的改动也要跑测试」更前一步：跑测试是发现自己错了，
读判据是根本不往那儿走。
