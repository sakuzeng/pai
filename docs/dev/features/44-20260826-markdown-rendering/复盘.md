# 44-markdown-rendering · 复盘

## 学到了什么

这一轮最有价值的一条不是我写的代码，是**两条为别的事写的 e2e 撞出了一个我
28 条单测全没抓到的真缺陷**。

`test_paging_up_moves_the_transcript_but_not_the_dock` 与鼠标滚动那条，
用「21 行的答案」把屏幕填满再滚动。它们要的是「有东西可滚」，
而我的渲染把 21 行合并成了一段——内容一个字没丢（我有 `test_nothing_is_lost`
钉这个），但结构没了。我的单测全在问「内容还在吗」「宽度对吗」，
没有一条在问「行还是不是那么多行」。

可复用的一条：**集成测试之所以抓得到单测抓不到的东西，不是因为它更全，
是因为它依赖一些「副产品」**——那两条测试依赖的是「答案有 21 行」，
而那从来不是它们要测的东西。这类隐式依赖平时是噪音（改点无关的东西它就红），
但恰恰是它们守住了单测的盲区。所以下次一批 e2e 因为「无关」的改动变红时，
先别急着改测试，先问那个「无关」是不是真的无关。

第二条，关于验收判据的强度。表格这件事我写了两条判据：
「每行 display_width 相等」与「每一列的起始列号在每行相同」。
第一条能被尾部补空格蒙混过去（首列宽了、次列窄了，总宽照样相等），
第二条才是「对齐」的定义。写第一条时我以为自己已经在按「可判定的判据」做了，
第二条是写测试写到一半才想到的——**判据本身也分强弱，而弱判据的绿是最像真的假象**。

## 哪里走了弯路，为什么

真跑冒烟看出的中文标点顶行首，与 feature 43 的空文件头是同一族第三次出现：
**所有断言都在看别处**。43 那轮是没人看输出的开头两行，这轮是没人看每行的第一个
字符。两次都是靠真跑用眼睛发现的。

我在 43 复盘里给自己开的方子是「至少有一条逐字比对整体输出的测试」，
这轮一开始就照做了（`test_the_whole_rendering_verbatim`）。但它没抓到禁则问题，
因为那条测试的样例里那一段中文正好不折行。方子是对的，剂量不对——
逐字比对只覆盖了它那一个样例，而排版缺陷是**在特定宽度下**才显形的。
后来补的两条禁则测试是对 8~40 每个宽度都跑一遍，那才是排版类断言该有的形状。

另一处小弯路：`_render_list` 我第一版写了一段自己都读不懂的东西
（试图在 `_wrap_spans` 之外给列表符号上色，写出了 `out[-len(out) + out.index(...)]`
这种句子）。停下来重看时发现正确做法是给 `_wrap_spans` 加一个前缀色参数，
三行就完了。写出自己读不懂的代码，基本上等于走错了路口而不是遇到了难题。

## 我现在质疑什么

一、`NO_LINE_START` 里我塞了 ASCII 的 `,.;:?!)]}%`。中文标点的避头是明确的排版
规则，ASCII 那半不是——英文里逗号顶行首本来就不会发生（英文按空格折行），
而我是按字符折行的，所以才会。也就是说我用一条排版规则去补一个**我自己的
折行算法造成的**问题。真正对的做法是英文按词折行（不在词中间断），
而我没做，只是给最刺眼的症状贴了块膏药。这条我写进 TODO 了，
但我想说清楚它不是「还没做的功能」，是「做错了一半又绕开了」。

二、我给「代码块不做右边框」写的理由是「长代码行可以折行而不是截断」。
复盘时发现这个理由站不住：加了右边框照样可以折行，只是每行要补到定宽而已，
多十行代码。真实原因是我当时不想写那十行。给一个偷懒的决定配一个像样的理由，
比直接说「这里我选了简单的做法」更糟——后者下一个人会重新评估，前者他会以为
已经权衡过了。（结论我不改：左栏形状确实够用；改的是理由。）

三、「模型写下换行就是想换行」这条我说得很肯定，但它其实是个假设。
模型也可能只是把长句子在源码里折了行（很多模型的输出确实会在 80 列附近断）。
如果是那样，硬换行就会把一句话切成两行显示。我没有任何数据判断哪种更常见——
只有一次真跑的印象。这条与 `MAX_DIFF_LINES` 那类拍脑袋常数不同：
它不是一个数，是一个关于模型行为的判断，而我把它写成了注释里的断言。

## 下次怎么做更好

排版类的断言要**对一个宽度区间跑**，不是对一个宽度跑。
这轮的禁则测试是 `for width in range(8, 40)`，一写出来就抓到了边界上的字符
丢失（避头时是挪还是复制那一处）；而所有单点宽度的断言都放过了它。
同理，表格、折行、缩进这些「在特定尺寸下才显形」的东西，
判据都该带一个循环。成本是几行，买到的是「我没试过的那个宽度也不许坏」。
