# 44-markdown-rendering 开发日志

## 动工前的核实（2026-08-26）

四条，每一条都决定了候选长什么样，也决定了这件事比想象的简单：

1. **TUI 里答案不是逐字上屏的**。`MessageDelta` 只累加进 `app._streaming`，
   到 `AssistantMessage` / `AgentEnd` 才由 `_flush_answer` 一次性 commit。
   于是 md 渲染最难的那个问题（表格没收完没法排版）在 TUI 里根本不存在。
2. REPL / once 是真的逐字写 stdout，那里渲染与流式是真冲突——所以拍板问 1 选了只做 TUI。
3. 运行时依赖只有 `openai` + `python-dotenv`，没有渲染库。
4. `width.display_width` 已经 CJK 感知且剥转义符，`theme.wrap` 折行时整段吞掉
   转义序列不计列。表格列宽必须靠它们。

另外发现 TUI 已经把一半的活干好了：`app._display_result` 早就分好了
「模型拿原文 / 终端拿消毒版」，`_tool_entry` 早就会把多行结果折成可展开条目。
先看「现有结构已经准备好接什么」比先设计「我要加什么」省一半工作
（feature 43 复盘里学到的那条，这轮又用了一次）。

## 实现（2026-08-26）

新增 `src/pai/tui/markdown.py`（约 340 行）：按行扫描分块，不建 AST。
块级：围栏代码块、标题、分隔线、表格、引用块、列表、段落。
行内：粗体 / 斜体 / 行内代码，**成对才算标记**。

接线：`app._answer_entry` 改成 `dynamic_entry(lambda w: _answer_lines(text, w, …))`
——存一份定死的行数组的话，拉宽窗口表格不会跟着变，而那是拍板问 4 里
「截掉的信息会回来」那条承诺的落点。
`settings.markdown_enabled`（`tui.markdown`，默认开）+ `interactive` 装配接线：
纯视觉改动必须留一个退得回去的口子（同 `tui.altScreen` / `tui.mouse`）。

红：模块不存在。绿：`tests/test_tui_markdown.py` `28 passed`。

三处设计上的取舍：

一、**先折行再上色**。反过来的话，一段样式被折断时 `RESET` 落在第二行、
第一行没有收尾，而渲染是按行独立发出去的——那一行的颜色会漏给后面。

二、**表格分隔行用 ASCII `-` 而不是 `─`**。框线字符在 Unicode 里是
East Asian Width = Ambiguous，`display_width` 按 1 列算，部分 CJK 终端按 2 列画。
落在标题下划线、列表符号、代码块左栏上只是整体右移一格，无害；落在表格里
会让整张表塌掉，而表格的全部价值就在对齐。

三、**代码块不做右边框**（拍板时给用户看的预览是个完整的框）。左栏 + 上下沿的
形状少了「每行补到定宽」这一步，于是长代码行可以折行而不是截断——
截断的代码复制出去是坏的。这条偏离记在档案而不是悄悄做掉。

## 既有 e2e 撞出的一个真问题（2026-08-26）

三条 e2e 变红。第一条是预期内的（列表符号从 `-` 变成 `•`，那条测试按源文本找标记），
另外两条揭出一个**真问题**：

`test_paging_up_moves_the_transcript_but_not_the_dock` 与鼠标滚动那条都用
`"第一次回答。\n甲0\n甲1…"` 这样 21 行的答案填屏，然后滚动。渲染之后它们滚不动了
——因为 CommonMark 的「连续行合成一段」把 21 行合并成了一段。
内容一个字没丢，但**结构没了**。

这不是测试的问题：对话文本与文档文本在这一点上取向相反。模型写下换行就是想换行
（无标记的枚举、短句分行都很常见），合并掉就是改了它的排版。
改成**单换行按硬换行处理**（GFM 的 `breaks` 那一档，各家聊天界面也都这么定）。
补了一条 `test_a_single_newline_is_a_hard_break_not_a_soft_one` 钉住。

值得记的是发现方式：这个缺陷我自己的 28 条单测一条都没抓到，
是两条**为别的事写的 e2e** 撞出来的——它们恰好依赖「答案有 21 行」这个副产品。

## 真跑冒烟与中文禁则（2026-08-26）

在 `_answer_lines` 上真渲染了一段带表格、列表、代码块的回答，两个宽度各看一遍。
表格对齐、压缩、代码块字面量都对，但看出一处中文排版硬伤：

宽 40 时一段中文折成了「…先一句话」/「，然后一个表格。」——**逗号顶在行首**。
中文排版的「避头」规则里那是硬伤，而我 28 条断言全在看宽度，
没有一条在看每行的第一个字符是什么（又一次「所有断言都在看别处」，
与 feature 43 的空文件头同族）。

补了 `NO_LINE_START` 与两条测试：一条钉「标点不许顶行首」，
一条钉「避头是把字挤下来，不是删掉或复制」——后者是这类改动最容易在边界上
丢一个字的地方，且丢一个字不会让前一条变红。

顺带把 `_wrap_spans` 改成逐字符攒 + 末尾 `_merge` 合并同色段：
不合并的话每个字都套一对转义序列，录制文件与 `screen.py` 的解析开销白涨一个数量级。
