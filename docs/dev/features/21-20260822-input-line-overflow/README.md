## 需求

出处：R4#27（2026-08-17 评审，严重度接近高）。`LineEditor.render(width)`
**收了 width 却完全没用**（editor.py:239-269）：每个逻辑行原样拼 prompt 返回。
超宽输入行的后果分两种形态、两种都坏：

- main-screen（DockRenderer）：终端自动折行，dock「我以为写了 1 行、实际占了 3 行」，
  相对光标移动全部错位——与 feature 12 满屏阶梯**同款根因**，只是这次从输入行进来；
- alt-screen：`_fit` 把行硬切到 width（altscreen.py:235），超出部分连同
  `CURSOR_MARKER` 一起被扔掉——硬件光标没了、打字不可见、IME 失锚。

触发条件不苛刻：粘贴一条长命令、或中文输入 50 个字（每字 2 列，96 列终端
50 字就超）。

验收标准：
1. 超宽单行在两种渲染器下都不再破坏布局（main 不错位、alt 不丢光标）；
2. `CURSOR_MARKER` 在任何输入长度下都存活于 render 输出中；
3. 光标移动（词跳/行首行尾/↑↓历史）在超宽行上行为正确；
4. e2e 各钉一条（真 pty 粘长行，断言 dock 结构与光标可见）；
5. 全绿，数字进 STATUS。

## 候选方案与确认

### 方案 A · 折行（显示层 wrap，逻辑行不动）

`render(width)` 把每个逻辑行按显示列宽折成多个显示行（复用 `theme.wrap` 的
宽度语义，但要**穿过 CURSOR_MARKER 与选区反显序列**——marker 零宽、
反显是转义序列，`theme.wrap` 已会跳过转义、`display_width` 已会剥 marker，
地基是现成的）。dock 高度随输入增长（DockRenderer 本来就支持变高）。

- 参照：**pi 与 CC 独立同选**。pi `packages/tui/src/components/editor.ts`
  是词级折行（word-wrap + 长词硬断，grapheme 感知）；CC 的输入框是折行的
  多行 textarea。两家独立收敛，与「120s/600s 超时」同级别的强信号。
- 优点：全文可见；与 pai 其余所有组件的行为一致（transcript/dock 全是折行）；
  main-screen 的高度账自然对上。
- 代价：光标 (row, col) 要从「逻辑行内偏移」换算成「显示行内偏移」；
  选区反显要跨显示行切段；编辑器测试要补一批。约束：折行按**字符边界**
  不做词级（pi 做了词级回退，pai 第一版不抄——词级是体验优化不是正确性，
  且中文没有词边界可言）。

### 方案 B · 横滚（单显示行 + 视口滑动）

每个逻辑行永远占一个显示行，光标快出视野时窗口右移（readline/传统 shell 形态），
两端加截断指示（`…`）。

- 参照：无——pi 与 CC 都没这么做（bash/readline 是，但那是无 TUI 的行编辑器）。
- 优点：dock 高度恒定（不随输入变高）；实现比 A 略省（不碰选区跨行切段）。
- 代价：超出窗口的内容不可见，粘贴长命令后**看不到自己粘了什么**（安全上
  恰是最该看清的时刻——粘贴进来的命令马上要被执行）；窗口滑动的宽字符
  对齐一样要算，省不了多少；与两家参照都不同，未来每个输入相关功能都要
  单独考虑「横滚下怎么办」。

### 方案 C · 最小止血（只救光标，不改形态）

`_fit` 与 DockRenderer 路径上保证 `CURSOR_MARKER` 存活：截断时若 marker 在
被切掉的部分，把尾部窗口平移让 marker 进视野。

- 优点：改动最小。
- 代价：只治 alt 的「光标消失」半边；main-screen 的高度错位**原样留着**
  （那是接近高的那一半）；且引入第三种形态（截断+跟随），将来还得返工。

### 确认

问 1（2026-08-22，AskUserQuestion 原文）：「R4#27：输入行超宽（粘长命令 /
中文 50 字即触发）现在 main-screen 下错位、alt 下光标消失。修成什么形态？」
- 候选 A·折行（推荐）：pi 与 CC 独立同选（pi editor.ts 词级折行、CC 多行输入框）。
  全文可见，dock 随输入变高；要做光标/选区的显示行换算。pai 第一版按字符边界折，
  不抄 pi 的词级回退（体验优化非正确性，中文也没词边界）。
- 候选 B·横滚：单显示行 + 视口滑动（readline 形态）。dock 高度恒定，但超出窗口的
  内容不可见——粘贴进来马上要执行的长命令恰恰看不清；两家参照都没这么做。
- 候选 C·最小止血：只保证 CURSOR_MARKER 不被截掉（alt 的光标救回来），
  main-screen 的高度错位原样留着，将来还得返工。改动最小。
选择：A 折行。（同轮一并拍板的另外三条小修不属于本档案，
记录在 TODO「R4#15~R4#28」条目：#16 按框分流、#25 放行安全三键、#19 最小修。）
