# 真用一次的发现清单（feature 45）

跑法：真 pai 进程 + 真 pty（100×40）+ 真模型（deepseek-v4-flash）+ 真仓库。
夹具 `pai_playground/real_run/drive.py`，机制照抄 `tests/test_e2e_tui.py` 的
`Session`，两处不同：不覆盖 `PAI_BASE_URL`/`DEEPSEEK_API_KEY`（那正是要验的），
不做断言只落屏幕文本。写操作类任务在仓库副本里跑，不动真仓库。

四次运行，累计约 20 万 token（v4-flash，费用可忽略）。

## A. 证伪类：我前四轮的推断被真跑推翻的

### A1. 工具建成了，但模型不选它们——瓶颈在提示层，不在工具

任务二明说「然后跑测试确认全绿」，`run_tests` **一次都没被调用**，
模型全程用 bash。

原因在 `build_system_prompt` 的输出里：整份系统提示只有**一句**工具引导，
而它是给 `edit_file` 的——

> 改代码时优先用 edit_file 做精确修改，而不是用 bash 或整文件覆盖。

`search_files` / `run_tests` / `git_read` 一句都没有。
而模型**确实听了那唯一一句**：两次 `edit_file`，用得对，连 docstring 都如实更新了。

A/B 实验（副本里加三句引导，跑同一个问题）：

| | 工具调用 | 其中 bash | 权限弹窗 |
|---|---|---|---|
| 对照组（今天的提示） | 8 | 4 | 4 |
| 实验组（+3 句引导） | 7 | 3 | 3 |

单独验 `run_tests`（实验组，任务「跑一下 tests/test_boundary.py」）：
**1 次调用、0 弹窗、9 秒完成**，尾部判决 `26 passed` 完整保留。
同样的意图在对照组里走 bash、7 次弹窗、烧完预算也没做完。

结论：四轮工具建设的收益被提示层卡住了。工具本身是对的
（一旦被选中，效果就是设计时想要的那样）。

### A2. 「把活从 bash 摘出来」只摘走了一半，剩下的有结构性原因

实验组剩下的 3 次 bash 全都不是「模型不听话」：

1. `pwd && ls` —— **pai 没有任何工具能回答「这个项目长什么样」**。
   这是每个 agent 会话的必然开场，而它必然弹窗。
2. `find src -type f -name '*.py' | head -50` —— 同上，要目录结构。
   `search_files(pattern="", glob=...)` 只能给一个扁平文件名列表，给不出树。
3. `grep -n 'MAX_OUTPUT_CHARS = ' src/pai/core/tools/output.py` ——
   **`search_files` 不接受单个文件当搜索根**，当场验过：
   `错误：搜索根 …/output.py 不存在或不是目录。`
   要在一个已知文件里找一行，今天只能走 bash。

## B. 真缺陷

### B1. markdown 折行把英文单词从中间劈开（高频，每屏都有）

真跑第一屏就撞上，宽度 100 与 80 都有：

```
还被 recall.py / rul
es.py 注释引用为「read_file 的那个 4000」
```
```
从 output.py 导入（from pai.co
re.tools.output import MAX_OUTPUT_CHARS）
```
```
MAX_OUTPUT_CHA
RS
```

这正是我在 feature 44 复盘里自己承认的那条欠账（「英文按字符折行，
我用 ASCII 标点避头去补自己折行算法造成的问题」）。
真跑把它从「我欠的账」升级成**实测确认的高频可见缺陷**——
模型的回答里几乎每段都有代码标识符，而它们全会被劈。

### B2. 编辑的 diff 在默认视图里等于没做

feature 43 让 `edit_file` / `write_file` 回一段 diff，
但 TUI 的工具结果行默认折叠，屏幕上只看到：

```
└ edit_file(path='src/pai/tui/width.py', old…) → 已在 src/pai/tui/width.py 中完成 1 处替换（第 30 …
```

diff 在第二行之后，要按 `^O` 才展开。也就是说「改了什么看得见」这个需求，
在默认视图下**没有兑现**——除非用户知道并记得按 ^O。

### B3. 长 cwd 把 footer 撑满

副本路径较长时 footer 变成：

```
/private/tmp/claude-501/-Users-sakuzeng-improve-coding-agent-projects-pai/367e694d-d932-4c14-99fc-4…
```

模型名与上下文占比（`deepseek-v4-flash · 1.3%/1.0M`）被整条挤掉了。
真仓库路径下正常，但这不是「路径太长活该」——footer 该按信息优先级取舍，
而不是先到先得。

## C. 体验摩擦

- **C1 权限弹窗文案是内部术语**：「`bash` 不参与工作目录边界判定（未声明路径语义），
  按最保守处理」。对着用户说 D#52 的实现细节，既没说清风险，也没给出路
  （比如「这条命令只是列目录，可以用 search_files」或「配 allow 规则」）。
- **C2 等人回答的时间算进了「用时」**：第一次跑显示 `⠹ 3m59s`，其中 3m55s 是
  弹窗在等我。计时器该在等人时停。
- **C3 默认 token 预算撑不过一个中等任务**：`--max-tokens` 默认 200k，
  实测一个 11 步的真实任务（改函数 + 加测试 + 跑测试）烧了 131820 token 就撞顶了。
- **C4 模型不知道自己的 cwd**：系统提示里没有工作目录，于是它每条 bash 都写
  `cd /private/tmp/... && …` 或 `git -C /private/tmp/... …`，
  既浪费 token 又让权限弹窗里的命令长得没法读。

## D. 正面确认（做对了的，一并记下）

- **D1** `edit_file` 的引导有效，模型两次精确替换都对，且如实更新了 docstring。
- **D2** markdown 渲染真的在工作：代码块框线、列表符号 `•`、行内代码剥标记，
  可读性明显好于原文。这一条是 feature 44 的正面验证。
- **D3** `run_tests` 一旦被选中就是设计时想要的样子：0 弹窗、9 秒、
  尾部判决完整（feature 42 的保头保尾在真输出上生效）。
- **D4** `search_files` 跨三次运行被选中 5 次，工具本身好用；
  它的问题在覆盖面（A2），不在质量。
- **D5** 8 个工具调用 13 秒完成一次跨文件溯源，性能没有问题。
