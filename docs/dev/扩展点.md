# 扩展点地图：「要加 X，去哪里」

出处：R4#E1（2026-08-17 评审，可扩展性改造第一条）。给要给 pai 加东西的人
（人或 AI）一张映射表：每类扩展该动哪些文件、必须连带做什么。锚点写符号名
不写行号（行号会漂）。写这张表的过程本身暴露了几个说不清的扩展点，
见末节「现在还说不清的」——那正是 E2~E5 的证据。

## 加一个工具

- 入口：`core/tools/` 下新文件，函数上挂 `@tool`（`core/tools/__init__.py`），
  参数用 `Annotated` 注解——schema 从签名生成，禁止手写 schema 字典
  （AGENTS「架构约束」第一条）。
- 必须连带的三件声明，一件都别漏（漏了不报错，静默退到最保守/最朴素档）：
  1. 能力标志 `capabilities_for`（`is_read_only` / `is_concurrency_safe`，
     默认全 False——漏了只是不并行，不算错）；
  2. 权限匹配语义 `matcher_for`（漏了退回朴素 fnmatch；碰路径的工具
     漏了这条会静默失去路径锚点语义，见 TODO「按参数语义挂匹配器」）；
  3. 边界声明 `get_path` / `access`（漏了 = 结构上不参与工作目录边界，
     bash 就是刻意两个都不声明，D#52）。
- 错误处理：工具内部异常必须转成字符串结果回填（`Tool.run` 已兜，
  但工具自己能给出更有用的错误文案就别指望兜底）。
- 测试：至少正常路径 + 一个错误路径（AGENTS「测试」节）；工具结果给终端
  看的那份要过 `tui/sanitize.py`（入口已接好，不用自己做）。
- 默认工具集：`get_tools()` 惰性注册；交互专属工具（如 `ask_user_question`）
  不进默认集，在 `modes/interactive.py` 装配期显式加。

## 拦一个工具调用 / 加一条权限规则

- 规则：`core/permissions.py`（三态 allow/ask/deny，求值顺序 deny→ask→allow
  不许改，D#46）；用户写在两层 `settings.json`（`core/settings.py` 读）。
- 目录边界：`core/boundary.py`（工作目录锚点、危险路径清单、符号链接双路径）。
- 外部拦截：PreToolUse hook（`core/hooks.py`，退出码 0/2/其他三态，
  崩溃/超时 fail-closed，D#54）。
- 装配点：`core/gate.py` 的 `make_before_tool_call`——loop 只认识这一个回调，
  新的拦截逻辑应该合进 gate 的装配，不要往 loop 里塞 if。

## 观察 / 记录发生了什么

- 加事件：`core/events.py` 新增 frozen dataclass → 进 `AgentEvent` Union →
  `render_text` 加一个分支（不想默认出声就返回 None）→
  `viz/collect.py` 的 `EVENT_SRC` 登记发射点（防漂移测试只校验键集合，
  校验不了「真有人发」——`TurnStart` 死事件潜伏 11 天的教训，
  2026-08-24 已删；发射点写完先真发一次再登记）。
- 消费：`on_event` 回调（loop 与 modes 都收）；落盘 `core/trace.py` 的
  `EventTrace`（写失败吞掉且只告警一次，观测流挂了不连累正事）；
  多个消费者用 `compose()` 扇出。
- 原则（R4 评审采纳，AGENTS「架构约束」）：新模块依赖 events.py 的事件与
  注入回调，绝不 import loop.py 内部。

## 加一种交互形态 / 界面元素

- 形态：`modes/` 一个文件一种（once / interactive；REPL 与 TUI 同在
  interactive，`_use_tui` 分流）。
- 装配：rules/hooks → skills 信任 → MCP 信任与并表 → boundary → gate →
  memory → recall 的共用序列住 `modes/assembly.py` 的 `assemble`
  （feature 31 起一份实现；此前 once 与 interactive 各手抄一份）。
  往装配段加东西改这里，两模式同时生效；模式差异（asker / 权限模式 /
  事件通道）走参数。MCP 关闭归各模式的单出口 finally，不在 assemble 里。
- TUI 组件：`tui/` 下实现 `Component.render(width) -> list[str]` 纯函数契约，
  组件不持终端句柄；碰终端的只有 renderer（DockRenderer / AltScreenRenderer）。
- 宽度一律 `display_width`（列不是字符数；调用方必须先过 `tui/sanitize.py`）。
- 新增 `/命令`：`modes/interactive.py` 的 `_handle_command` 加分支 +
  `HELP` 文案同步；对话框期间要不要放行由 `dialog.handoff` 前缀语义决定。
- 新增按键动作：`tui/app.py` 的 `_key` 产出动作，三个消费点都要考虑
  （空闲主循环 / busy 期 `on_event` poll / 对话框期 `on_action`）——
  R4#25 的教训是只接了空闲那处，另两处静默丢弃。

## 加持久记录

- 会话：`core/session.py` 的 `SessionLog`（append-only JSONL，每条带
  sessionId/cwd）。新记录类型直接 append dict；注意现状顶层判别字段不统一
  （消息用 `role`、其他用 `type`），改造归 R4#A1 会话格式立项，别单点打补丁。
- 落盘位置：`core/paths.py` 是用户级路径唯一事实源，别自己拼 `~/.pai`。

## 加指令 / 记忆来源

- 分层指令发现与 `@` 导入：`core/memory.py`（`discover`、`expand_imports`）。
- 自动记忆写入：`core/tools/memory_tool.py`（一事一文件带 frontmatter，
  `MEMORY.md` 是投影不是账本，D#55）。
- 按查询召回：`core/recall.py`（侧查询选 ≤5 篇注入 system-reminder；
  usage 计进预算，连续失败熔断）。

## 改模型 / 协议 / 配置

- client 与模型名：`config.py`（OpenAI 兼容协议；`PAI_BASE_URL` 换端点）。
- 流式装配：`core/streaming.py` 的 `assemble`（一次响应一条消息 D#57、
  usage 每块都看 D#58、tool_call id 守卫 R4#9——改协议行为先读它头部注释）。
- 设置项：`core/settings.py` 两层 `settings.json`；环境变量只留给
  「跑一次就变」的开关（`PAI_CONTEXT_WINDOW` 这类），长期配置进 settings。

## 现在还说不清的（写表过程中暴露，即 E2~E5 的证据）

- system prompt 没有缝：`loop.py` 的 `SYSTEM_PROMPT` 是常量，硬编码了
  「你有这些工具：bash、read_file、write_file、edit_file」——而 REPL 实际
  会加 `ask_user_question`、`visible_tools` 会按 deny 规则删减，常量已经
  在对模型说谎。加 skills 更没有落点。→ R4#E2。
- 「模型可见 == 已落盘」没有不变量：append 进 messages 与 append 进 session
  是散在各处的成对操作（`_extend` 只是雏形），漏一半不会红。→ R4#E3。
- ~~工具只有一个来源~~ 2026-08-23 起有两个（feature 29）：`get_tools()` 直读
  进程级 REGISTRY + MCP 远程工具经 `core/mcp.bridge_tools` 在装配层
  setdefault 并表（schema 同源约束的破例记 D#74）。正式 ToolSource 协议
  刻意未立——第二来源只此一家，等第三来源出现再抽。
- 工具结果没有后处理缝：结果回填是硬编码路径，microcompact / 结果剪枝
  这类「回填前改写」today 无处可挂。→ R4#E5（真实需求出现再开）。
