## 三、可扩展性改造（对照 deepseek-harness）

用户提问：「想让 pai 之后可扩展性较高，像 deepseek-harness 一样，该怎样修改」。

### dsh 的可扩展性来自哪（证据分档：一方源码+一方文档）

① Cordis 插件框架——一切皆插件，服务挂 ctx 键（agent-loop 源码验证
`static inject = ['agents','sessions','llm','tools','systemPrompt']`）；
② capability seam 三角（接口/提供方/消费方）——shell 有 bash-local/bash-sandbox/
pwsh-local 三提供方、llm 有 deepseek/pi-ai/replay、session-persistence 有
jsonl/sqlite，目录结构印证；③ 工具执行 pre/execute/post 三段 waterfall 中间件
（源码验证）；④「模型可见即已记录」运行时不变量（`ctx.invariants` 真实存在）；
⑤ profile 分层装配（仅文档层证据）；⑥ 文档末尾「新行为归属位置」映射表本身
就是扩展性机制。

### pai 的现状：已无意识长出微型版

「框架问、工具答」（`Tool.matcher`/`get_path`/`is_read_only`…）就是 seam 思想；
events.py + SessionLog + trace.compose 对应 dsh 的事件双域；`run_agent` 的
15 个 keyword-only 参数就是 pai 尺寸的 ctx。方向没错，差距集中在四处：

1. **工具来源是单一全局 REGISTRY**（tools/__init__.py:17,190），import 即注册——
   MCP 工具（运行期发现、schema 来自服务器）结构上进不来，且与「schema 与
   代码同源」约束正面冲突；
2. **工具流水线只有执行前一个缝**（before_tool_call）——TODO 里的 microcompact
   / 结果剪枝需要的 post-execute 缝不存在；
3. **messages 与 session 人肉配对**（loop 约 8 处成对 append）——「模型可见即
   已记录」只是习惯不是不变量，「中断丢半条消息」正是缝隙产物；
4. **SYSTEM_PROMPT 硬编码且逐字列举四个工具名**（loop.py:75）——加第五个工具
   提示词就开始撒谎（R3#5 已登记，这里升格为扩展性主线）。

### 改造建议（按序）

- [ ] **R4#E1（P1，纯文档零风险）**「要加 X 去哪里」映射表进 docs/dev/：
      加工具→`@tool`+三件声明；拦截→gate/hooks；观察→on_event+EventTrace；
      加交互形态→modes/；加持久记录→SessionLog 记录类型。写的过程会暴露
      哪些扩展点说不清——说不清的就是下面几条的证据。
- [ ] **R4#E2（P1）system prompt 从常量变装配**：工具清单部分由装配层按实际
      tools 生成，loop 收注入的 prompt/builder（与 instructions 回调同款先例）。
      skills 阶段必然要注入 skill 目录，这个缝现在不开、届时就是打补丁。
      默认参数不传时行为逐字不变。
- [ ] **R4#E3（P1）「模型可见即已记录」升格为不变量**：不抄 event-sourcing 重构
      （那是 fork/多前端的规模需求）；最小做法 = ① append 成对操作收口到一个
      函数（`_extend` 已是雏形）；② 加一条测试级不变量——回放任一会话 JSONL
      能重建发给模型的 messages。这直接是 evals 阶段的地基，也顺手钉住 R4#5。
- [ ] **R4#E4（P2，MCP 立项时一并做）ToolSource seam**：定义「产出
      dict[str, Tool]」的协议，装配层合并多 source——本地 REGISTRY 是第一个，
      MCP client 是第二个；远程工具构造 Tool 时能力字段取最保守档。
      **必须配 decisions**：「schema 与代码同源」改述为「本地同源；远程以
      服务器声明为准」。
- [ ] **R4#E5（P3，需求出现再做）after_tool_call 对称缝**：驱动力必须是
      microcompact 或结果剪枝的真实需求，现在开是空转。

**点名不抄的**（dsh 的规模需求，pai 现阶段属过度设计）：Cordis 全插件化、
profile/patch 分层、api-gateway/typert/HMR、subagent 多后端矩阵、waterfall
事件总线。倒有一条原则可零成本采纳进 AGENTS.md：**新模块依赖 events.py 的
事件与注入回调，绝不 import loop.py 内部**（dsh 对 agent-loop 的同款戒律）。
