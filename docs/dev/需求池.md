**用户提出的想法在这里落地，然后才决定去哪。** 与 [TODO.md](TODO.md) 的分工是硬的：
TODO 是「**已确认要做**的事」，这里是「**想要但还没评估**的事」——混在一起会稀释 TODO
那句「唯一待办入口」的权威性。

## 规矩（三条）

1. **一行一条，记原话，不转述。**
   转述会丢掉决定性的细节：2026-08-10 「点一下展开」这五个字直接决定了需求归属 TUI 阶段；
   同一天我把「`.env` 按包位置解析」转述成「pai 起不来」，差点修错方向。
2. **三种出路，必须标注**：
   - **升格** → 立 [features/](features/README.md) 档案，走 brainstorm → spec → plan；
   - **降格** → 小改动，直接进 TODO 一行；
   - **不做** → 划掉 + 一句理由（**保留记录，不删**）。
3. **不许长期堆积**：每个路线图阶段动工前清一次。

- **2026-08-10（用户）**：「当前的 session 存的 json 中的字段可以借鉴下 cc 中的字段吗」
  → **部分并入 08，其余待评估**。实地对照了真实 CC 会话文件（只取字段名不读内容）：

  **第一档·该抄**：`sessionId`（pai 没有，文件名靠时间戳，同秒会撞——R#15 旧账）、
  `uuid` + `parentUuid`（每条记录有 id 并指向父记录，是 `--resume`/回退/分支重开的地基）、
  `cwd`（pai 完全没记；08 把会话集中存之后不记就是净信息丢失）、
  `timestamp` 用 ISO（pai 现在是 epoch 浮点）、`version`（回放老会话能解释格式差异）、
  `gitBranch`（配套刚立的分支规矩）。

  **第二档·知道就好**：`isSidechain`（子 agent，已裁定不做）、`requestId`、
  `file-history-snapshot`/`delta`（**checkpointing 的地基**——记录改文件前的快照以支持回滚）、
  `queue-operation`（排队消息记录，正好对应双队列）、`mode`/`permission-mode`（阶段 4 后可能有用）。

  **第三档·不抄**：`ai-title`、`last-prompt`、`attachment`、一堆 `hook*`。

  **架构上最值得学的一点**：CC 的 `type` 是**顶层唯一判别式**，而 pai 混用两套——
  消息用 `role`、其他记录用 `type`，分类脚本得写 `r.get('type', r.get('role'))` 才跑得动。
  一个 JSONL 里的记录应该只有一个判别字段。

  **为什么不整个并进 08**：08 是**搬家**（纯位置变更，验收清晰），字段变更是**换格式**
  （影响阶段 7 的回放/evals、要决定旧文件兼不兼容）。混在一起会让 08 的验收变模糊，
  格式若返工搬家也跟着卡住。**只把 `sessionId` + `cwd` 并进 08**——本来就要动 `SessionLog`，
  各一行，且 08 之后不加 `cwd` 就是信息丢失。其余（`uuid`/`parentUuid` 的父子链、
  ISO 时间戳、统一判别字段）**待立独立档案**。

## 已裁决

- **2026-08-10：`pai_playground/` 正式化为「手工真跑的沙盒」，但自动化测试不用它。**
  用户提议「所有和测试有关的都在此目录模拟」。裁决为**分两种**：
  - 手工冒烟 / 真跑 pai → `pai_playground/`（需要事后翻看产物，固定位置是优点）；
  - 自动化测试 → 继续 `tmp_path` + `tests/conftest.py` 的 `$HOME` 隔离。
  **理由**：当天那个「测试污染用户 `~/.pai`」的 bug，性质是**「测试写进了一个它管不着的
  固定位置」**。把固定位置从 `~/.pai` 换成 `pai_playground/` 只是换个地方拉，
  同一类 bug 还在（测试之间互相看见残留、跑两次结果不同）。`tmp_path` 才是对症的。
  衍生：真跑产生的轨迹一旦被当测试夹具用，须复制进版本库（解决 TODO 里
  「pai_playground 被 gitignore，夹具溯源链断了」那条老债）。
