# 路径边界判定：把「这个文件在不在允许范围内」写对

- 来源：无单一外部原文。CC `src/utils/permissions/filesystem.ts` 的实现与注释
  （见 [source-walks/cc-pi-permission-boundaries.md](../source-walks/cc-pi-permission-boundaries.md)）
  + POSIX 路径语义 + 2026-08-11 在 pai 上的实测（features/09 的四条注入反证）
- 精读日期：2026-08-11
- pai 锚点：`src/pai/core/boundary.py`、docs/dev/decisions.md #51 #52

任何要限制「agent / 插件 / 沙箱进程只能碰某些目录」的系统都会撞上这四条。
换语言换项目结论一样成立——它们的根源是路径这个东西本身，不是某家的实现。

## 一、前缀不等于包含（最容易写、最容易错的一条）

```python
"/tmp/proj-evil".startswith("/tmp/proj")   # True —— 但它显然不在 /tmp/proj 里
```

边界判定写成朴素前缀比较，攻击者在项目旁边建一个 `<项目名>-evil` 就越界了。
必须比到**路径分隔符边界**：

```python
target == base or target.startswith(base.rstrip(sep) + sep)
```

写测试时先断言「朴素前缀确实会误判」再断言「我们没误判」——
否则这条测试在实现正确时和实现错误时看起来一样。

## 二、边界锚点与路径解析锚点，是**两个**锚点

这条最反直觉，也最容易被合并成一个：

| | 用哪个 cwd | 为什么 |
|---|---|---|
| 边界集合 | **启动时的 cwd** | 进程中途 `cd` 出去，边界不该跟着跑 |
| 相对路径解析 | **当前 cwd** | 工具真正 `open()` 的就是那个路径 |

合并成「都用启动 cwd」会造出一条 **cd 逃逸**：

```
cd /etc && read_file("passwd")
  → 按启动 cwd 解析成 <proj>/passwd → 判定「界内」→ 放行
  → 实际打开的是 /etc/passwd
```

合并成「都用当前 cwd」则边界形同虚设（`cd /` 之后全世界都是界内）。
两个锚点必须分开，且各自有测试。

## 三、符号链接要**两条路径都查**，而且 allow / deny 的语义是反的

一条路径要展开成「原始路径」+「realpath 解析后的路径」两条：

- **deny / ask：任一条脏就拦**（软链指向敏感位置 → 拦）
- **allow：两条都干净才放行**（名字在 `src/` 下、真身在界外 → 不放行）

这个不对称不是洁癖——只做 deny 那一半，`allow=["read(/src/**)"]` 会放行
一条指向 `/etc/shadow` 的软链;只做 allow 那一半,deny 规则一条软链就绕开了。

**第三条容易漏的**:**允许目录本身也要用同一个函数解析**。不对称解析会造成**误拒**——
待查路径 realpath 之后是 `/private/var/...`,拿它跟未解析的 `/var/...` 比永远不匹配,
于是把本该放行的全拒了。CC 的源码注释专门标了这个坑（举的例子是 macOS 的
`/System/Volumes/Data/...`）。

**代价要知道**:realpath 是 syscall。CC 的注释提到不缓存的话一次权限检查会做到
30 次 syscall,所以它把「一次算好、全链共用」写进了函数签名（把结果 threading 下去），
并对会话级不变量（允许目录集合）做 memoize。

## 四、判不出来 ≠ 没问题

三个具体位置,都该落到最保守的一档:

```python
paths_all_inside([])        # False,不是 all([]) 的 True
contains("")                # False —— 取不到路径时不放行
没声明路径语义的工具          # 不参与边界判定 → 兜底走最严的档
```

`all([]) == True` 是数学惯例,在权限判定里是个陷阱:空集合意味着
「我没拿到任何可判定的东西」,而那恰恰是最不该放行的时刻。
同理,子进程门禁超时/起不来时返回「无意见」而非「拒绝」,等于让一次失败变成一次放行。

## 五、这一套挡不住什么（边界要说清楚）

- **挡不住能执行任意命令的工具**。路径边界建立在「工具声明了它碰哪个路径」之上;
  `bash("cat ../secret")` 的路径在命令字符串里,不做 shell 语义分析就看不见。
  CC 用分类器模型补这一段,没有分类器就只能承认这个洞（pai D#52）。
  **危险在于它的失效点在「用户为了可用性配白名单」那一刻**,不在默认配置里。
- **挡不住 TOCTOU**。检查与打开之间有窗口,期间软链可以被换掉。
  真要堵得靠 OS 级机制（`openat` + `O_NOFOLLOW`、容器、沙箱）。
- 前缀匹配式的规则**挡手滑不挡对抗**——官方原话就是这么写的。
