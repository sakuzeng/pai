# raw mode 下终端的三条反直觉语义

- 来源：无单一外部原文。POSIX termios 语义 + 2026-08-11 在 pai 上撞出来的实况
  （真 pty 探针与用户真跑，见 docs/dev/features/12-20260811-tui/）
- 精读日期：2026-08-11
- pai 锚点：`src/pai/tui/terminal.py`、`src/pai/tui/keys.py`、`src/pai/tui/app.py`、
  features/12-20260811-tui

自己画终端界面就得进 raw mode（关行规程的回显与行缓冲）。
这三条**在进 raw mode 的那一刻起就变了**，而它们都不会报错、只会静默地坏。
每一条 pai 都实撞过，代价从「排版难看」到「程序完全死住」。

---

## 一、`input()` / `readline()` 在 raw mode 下**永远等不到行尾**

行规程（canonical mode）的工作是把 `\r` 翻译成 `\n` 再交给程序（`ICRNL`）。
raw mode 把它关了，于是：

- 用户按 Enter，程序收到的是 **`\r`**；
- 而 `input()` / `fgets()` / 任何「读到换行为止」的 API 等的是 **`\n`**；
- 两者永不相遇 → **调用方无限期阻塞**。

同时 `ISIG` 也被关掉：

- Ctrl+C 不再产生 `SIGINT`，只是一个 **`0x03` 字节**；
- Ctrl+D 不再产生 EOF，只是 **`0x04`**。

**合起来的后果是最坏的那种**：程序卡住，而所有平时用来脱身的键**全部失效**——
用户只能杀进程。

> **pai 的实撞**：TUI 起来后权限对话框走了旧的问答通道（它调 `input()`），
> 整个程序死住、Ctrl+C 与 Ctrl+D 都不管用。
> 判据：**进 raw mode 之后，代码里任何一处 `input()` 都是一颗定时炸弹**——
> 不是「可能不好用」，是「一旦走到就必死」。改造终端界面时，
> 先把所有阻塞式行读取找出来，而不是等它被某条冷门路径走到。

## 二、终端会替你折行，而你的光标算术不知道

只要写出去的一行超过终端宽度，终端**自动折行**：它在屏幕上占了 2 行、3 行。
而应用侧如果按「我写了 1 行」记账，之后所有的相对光标移动
（`CSI nA` / `CSI nB`）都会错位，且**误差会累积**——
屏幕上的表现是文字一行比一行往右斜，像阶梯。

两个都要做：

1. **拆掉内容里的 `\n`**——一个带换行的字符串写出去就是多行，别当成一行记账；
2. **按显示列宽自己折行**，不要把折行的决定权交给终端。

折行还必须**跳过转义序列**：按字符切会把 `\x1b` 当成 1 列
（宽度算错），而且可能把一条序列**切成两半**，后半截就作为可见字符打了出来。

> **pai 的实撞**：工具结果是一整个带 `\n` 的字符串，被当成「一行」交出去 → 满屏阶梯。
> 修法是在「上交给屏幕」这个唯一出口处强制拆行 + 折行，而不是在每个调用点各记各的。

## 三、emoji 不能用来做界面字形

两个独立的问题，都只在**别人的终端上**才暴露：

1. **字体覆盖**：emoji 不在等宽字体里，缺字就渲染成 ▯（豆腐块）。
2. **宽度不确定**：很多 emoji 的 East Asian Width 是 `W`（2 列），
   但有的终端按 1 列排版；带变体选择符（U+FE0F）时更乱。
   **只要终端与应用对宽度的判断差一列，整行的光标定位就错。**

所以界面自己的字形（提示符、列表记号、分隔线、状态图标）应当用
**文本呈现的符号**：`●`（U+25CF）、`✳`、`└`、`─`、`❯`、`⧗` 这一类——
码位低、字体覆盖率高、宽度确定为 1。

这条容易被当成审美问题轻轻放过，**它不是**：它会让光标算术错位，
进而把上面第二条的症状再制造一遍。

> **pai 的实撞**：答案前缀用了 `🤖`，用户终端上渲染成方块。
> 换成 `●` 之后另加了一条测试，遍历界面用到的每一个字形，
> 断言「码位 < U+1F000」且「不是宽字符」且「显示宽度恰好 1」——
> 加新字形时忘了这条会当场变红。**审美判断不好测，物理约束好测**，
> 那就把物理约束测住。

## 附：退出时必须无条件复原

raw mode、bracketed paste、鼠标上报、隐藏光标——这些都是**对终端的全局状态修改**。
进程异常退出而没复原，用户的 shell 就坏在那儿（打字没回显、Ctrl+C 不管用），
只能 `reset` 或关窗口。

所以复原要满足两点：

- **无条件发**：不做终端能力检测（检测本身不可靠；不支持的终端上这些序列是 no-op）；
- **每一步互不依赖**：写终端失败也不能跳过恢复 termios——两件事分开 try。

## 五、进了 raw mode 之后，下一个问题通常是「要不要连屏幕一起接管」

raw mode 解决的是「按键怎么进来」，**没解决「画在哪儿」**。
应用只画屏幕底部若干行（main-screen）还是整屏都归自己（备用屏），
是另一个独立的选择，它带来另一批坑：DECSET 1049 不幂等、鼠标上报三档互斥、
拿走鼠标就等于拿走终端原生的选中复制、备用屏 resize 后不重绘就是脏的。
见 [alt-screen-and-mouse.md](alt-screen-and-mouse.md)。

一条容易漏的顺序约束：**「进备用屏」必须早于「画第一帧」**——
顺序反了的话第一帧落在主屏上并被保存下来，**退出备用屏之后**才作为一坨脏东西出现。
症状离故障点隔了整整一个会话。
